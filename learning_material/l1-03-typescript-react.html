L1.03

Prerequisites II: TypeScript and React, enough to read every line

Recipe card75 min
You need
L1.02; Node installed is helpful for the examples (see L1.05)
You'll produce
A tiny counter + timer component that uses every hook our app uses

In two sentences: Our app is written in TypeScript (JavaScript plus types) using React (a library that turns state into UI). This lesson teaches the exact features the code uses: unions, generics, !, as, JSX, props, useState, useEffect, useRef, useMemo, useCallback, context, keys and the rules of hooks. It shows them in our real code.

By the end, without notes, you can

  1. Read any type annotation in the codebase, including unions like "cards" | "quiz" | "list", generics like load<T> and the ! operator.
  2. Explain React's render → commit → effect cycle and what a dependency array does.
  3. Choose correctly between useState, useRef, useMemo and useCallback for a given need.
  4. Build a context provider plus a custom hook (useAuth) and explain why it avoids prop drilling.
  5. State the rules of hooks, and explain why Me() puts its if (!profile) return null after its hooks.

2

The problem this solves

Plain JavaScript lets you write question.answr and only find the typo at runtime, on a student's phone. Plain DOM code (document.createElement, manual updates) gets tangled when one change, like marking a card known, must update the deck counter, the Home stats and the week tile. TypeScript catches the typo while you type. React lets you describe what the screen should look like for a given state, and it works out the DOM changes.

TypeScript in 20 minutes (only what we use)

Self-check:

  1. What does type Mode = "cards" | "quiz" | "list" allow?
  2. What is T in function load<T>(key: string, fallback: T): T?
  3. What does profile!.display_name promise the compiler?
  4. What does import type { Session } from "@supabase/supabase-js" do at runtime?
Answersreveal
1. Only those three exact strings. 2. A type parameter: the caller's fallback type becomes the return type. 3. "This is not null or undefined here, trust me." It is unchecked at runtime. 4. Nothing: it is erased; only types are imported.

3.1 Annotations and object types

TypeScript8 lines
export type Question = {  id: number;          // week*100 + number, matches public.questions.id  week: number;  q: string;  options: string[];   // array of strings  answer: number;      // 0-based  note?: string;       // ? = optional: string | undefined};

That is the real type from src/data/questions.ts. Now q.answr is a compile error, and q.note.length is an error too ("possibly undefined"). TypeScript forces you to handle the missing note.

3.2 Union and literal types

TypeScript3 lines
type Mode = "cards" | "quiz" | "list";type Mark = "known" | "again";type ThemePref = "system" | "light" | "dark";

A union of string literals is an enum without the ceremony. setMode("lsit") fails to compile. Postgres enforces the same set server-side with check (status in ('known','again')), so the two layers agree (L2.02).

3.3 Generics: one function, many types

TypeScript12 lines
// src/lib/storage.ts (real)export function load<T>(key: string, fallback: T): T {  try {    const v = localStorage.getItem(key);    return v ? (JSON.parse(v) as T) : fallback;  } catch {    return fallback;  }}// callers:const pref = load<ThemePref>("pol.theme", "system");   // ThemePrefconst marks = load<Marks>("pol.marks", {});              // Marks

Why. JSON.parse returns any (no type information), and as T labels it. That label is an assertion, not a check. If someone stored garbage, the type is a lie. We accept that for our own keys.

Generic components exist too: Segmented<T extends string> in L2.06a accepts any string union, so value and onChange stay in sync.

3.4 !, as, and why they are sharp knives

  • document.getElementById("root")! is fine: we wrote index.html, and #root exists.
  • profile!.display_name was the sign-out crash. During the exit animation, profile was null. The ! silenced the compiler, and the app died at runtime (L2.07b). The fix was a real check: if (!session || !profile) return null;.
  • data as Stats labels untyped API data. Prefer real validation where it matters. Here the server is ours.

3.5 Modules, JSON imports and import type

TypeScript3 lines
import raw from "./questions.json";                     // Vite turns JSON into a JS valueimport { createClient } from "@supabase/supabase-js";   // named importimport type { Session } from "@supabase/supabase-js";   // type-only, erased at build

Our tsconfig.json sets verbatimModuleSyntax: true. That forces import type for type-only imports, so the compiled JS never tries to import something that does not exist at runtime (L2.04).

React: the model

Self-check:

  1. Is a component a function that returns HTML?
  2. When does useEffect(fn, [a]) run fn?
  3. Why does React need key on list items?
  4. What happens to count immediately after setCount(count + 1) inside the same handler?
Answersreveal
1. It returns a JSX description (objects), not HTML; React turns it into DOM. 2. After the first commit and after any commit where a changed (compared with Object.is). 3. To match items between renders, so state and animations stay with the right item. 4. Nothing: count is a constant for this render; the new value appears on the next render.

4.1 JSX and components

Definition. A component is a function from props to a UI description. JSX is HTML-like syntax that compiles to function calls.

TSX10 lines
function Stat({ value, label }: { value: string; label: string }) {  return (    <div className="stat">      <div className="v">{value}</div>      <div className="k">{label}</div>    </div>  );}// usage<Stat value="12/130" label="Cards mastered" />
  • className, not class (class is a JS keyword).
  • {expr} embeds any JS expression.
  • style={{ width: 120 }}: the outer braces mean "JS here"; the inner pair is an object.
  • {cond && <X/>} renders X only if cond is truthy. {a ? <X/> : <Y/>} picks one.

4.2 State and the render cycle

Definition. const [x, setX] = useState(initial) gives you a value that survives re-renders and a setter that schedules a re-render.

Step-through frames: the flashcard counter. The code (simplified from Study.tsx):

TSX2 lines
const [pos, setPos] = useState(0);const decide = () => setPos((p) => p + 1);   // functional update
Order ticketState and the render cycle1 / 5
Focus the ticket: ← → step · Space plays
  1. Event mount
    pos in this render0
    What React doesrenders card #1
    Which card shows?
  2. Event tap "Got it" → decide()
    pos in this render0 (unchanged during the handler)
    What React doesqueues p => p + 1
    Does pos change inside the handler?
    No
  3. Event re-render
    pos in this render1
    What React doesrenders card #2, commits
  4. Event double-tap fast: decide(); decide();
    pos in this render1
    What React doesqueues two updates: 1→2, 2→3
    Final pos?

  5. Event (if we had written setPos(pos + 1) twice)
    pos in this render1
    What React doesboth compute 1 + 1
    Final pos?
    2: one tap lost

Why our code uses functional updates. Frame 5 is a real class of bug. setPos((p) => p + 1) always uses the latest value. You will see setA((cur) => …) throughout the test runner.

Lazy initial state. useState(() => load("pol.shuffle", false)) runs load only on the first render, not on every render.

4.3 Effects: syncing with the outside world

Definition. useEffect(fn, deps) runs fn after commit, when deps changed. If fn returns a function, React calls it as cleanup.

Real example (src/lib/theme.tsx, listening to the OS dark-mode switch):

TSX6 lines
useEffect(() => {  const m = window.matchMedia("(prefers-color-scheme: dark)");  const on = () => setSystemDark(m.matches);  m.addEventListener("change", on);  return () => m.removeEventListener("change", on);   // cleanup: no leaked listeners}, []);                                                 // [] = only on mount/unmount
  • No deps array means it runs after every render. We do this deliberately for keyboard listeners that need fresh closures (the Study cards), and remove the old listener each time.
  • StrictMode (development only) mounts, unmounts and mounts every component once more, to flush out effects without proper cleanup. If your effect breaks when run twice, it was already broken.

4.4 Refs: memory that doesn't re-render

const r = useRef(value) gives { current }. It persists across renders, and changing it does not re-render.

  • DOM access: codeRef.current?.focus() focuses the code input.
  • Remembering a value between renders: lastPool.current is how we fixed the double shuffle in the quiz (L2.08b).
  • Collections that shouldn't trigger renders: againIds.current (a Set of ids marked "again").

4.5 useMemo and useCallback

  • useMemo(() => expensive(a), [a]) caches a value: perWeek progress on Home, the filtered pool of questions.
  • useCallback(fn, [deps]) caches a function identity. That matters when the function is itself a dependency of an effect. Example: build in the flashcards, used by useEffect(() => { build(); }, [build]).

4.6 Context: shared state without prop drilling

Definition. Context passes a value to every component below a provider, without threading props through each level.

TSX9 lines
// pattern used by ThemeProvider, AuthProvider, ProgressProviderconst Ctx = createContext<AuthState>(defaultValue);export function AuthProvider({ children }: { children: ReactNode }) {  const [session, setSession] = useState<Session | null>(null);  return <Ctx.Provider value={{ session /* … */ }}>{children}</Ctx.Provider>;}export const useAuth = () => useContext(Ctx);   // custom hook// any component:const { session } = useAuth();

4.7 Lists and keys

TSX1 line
{deck.slice(pos + 1, pos + 3).map((q, i) => <motion.div key={q.id} … />)}

key must be stable and unique among siblings. We use question ids. In the swipe card we use key={current.id + ":" + pos}, so undo (same question, new position) creates a fresh card that animates in.

4.8 The rules of hooks, and the sign-out bug

  1. Call hooks only at the top level of a component or custom hook. Never inside conditions, loops or after an early return.
  2. Call them in the same order on every render. React identifies each hook by its call order.
TSX8 lines
function Me() {  const { session, profile } = useAuth();    // hook 1  const [editOpen, setEditOpen] = useState(false);   // hook 2  const [toast, setToast] = useToast();      // hook 3  if (!session || !profile) return null;     // ✓ early return AFTER all hooks  const name = profile.display_name;  …}

If the return null came before useState, one render would call 1 hook and the next would call 3. React would throw "Rendered more hooks than during the previous render."

4.9 Class components (one place only)

Error boundaries must be classes. Only classes have componentDidCatch and static getDerivedStateFromError. It is our single class in the app (L2.05).

First working slice: one component using every hook

Create Counter.tsx (you will run it in L1.05's scaffold):

import { useCallback, useEffect, useMemo, useRef, useState } from "react"; export function Counter() {  const [n, setN] = useState(() => Number(localStorage.getItem("n") ?? 0)); // lazy init  const clicks = useRef(0);                                  // no re-render on change  const parity = useMemo(() => (n % 2 === 0 ? "even" : "odd"), [n]);  const inc = useCallback(() => {    clicks.current++;    setN((x) => x + 1);                                      // functional update  }, []);   useEffect(() => {    localStorage.setItem("n", String(n));                    // sync to the outside world  }, [n]);   useEffect(() => {    const k = (e: KeyboardEvent) => e.key === "ArrowUp" && inc();    window.addEventListener("keydown", k);    return () => window.removeEventListener("keydown", k);   // cleanup  }, [inc]);   return (    <button onClick={inc}>      {n} ({parity}) · clicked {clicks.current}×    </button>  );}

Done when: the number survives reload, ↑ increments it, and you can explain why clicks.current only shows the new value after the next render.

6

Check yourself

Answer each one before you look. Multiple-choice questions mark your pick and let you try again; for open questions, answer aloud, then reveal and grade yourself honestly.

Q1
setPos(pos + 1) is called twice in one handler, with pos = 4. What is pos next render?
B. Both calls compute 4 + 1. Use setPos(p => p + 1) to get 6. A assumes state updates instantly inside the handler, which is the core misconception.
Q2
You want to remember "the pool we last shuffled", to avoid reshuffling on mount, without causing a render. Use:
B. A ref persists and doesn't re-render. A would re-render when set. C recomputes from inputs and is not a writable memory.
Q3
Why does ProgressProvider sit inside AuthProvider?
B. A component can only read contexts provided above it. Placed outside, useAuth() would return the default value (no session) forever.
Q4
An effect adds a keydown listener and has no cleanup. In development the handler fires twice per key press. Why?
B. StrictMode's double-mount exposes the missing cleanup. In production the leak would build up across navigations instead.
Q5
Which line can crash at runtime even though TypeScript compiles it?
B. ! disables the null check. If profile is null at runtime, you get TypeError: Cannot read properties of null. That was our sign-out crash.

function useCountdown(seconds: number) {  const [left, setLeft] = useState(seconds);  useEffect(() => {    const t = setInterval(() => setLeft((s) => (s > 0 ? s - 1 : 0)), 1000);    return () => clearInterval(t);   // StrictMode's remount clears the first interval  }, []);  return left;}

Flashcards

See all 9 cards as a listfor a quick scan
  1. What does a string-literal union type give you?
    A closed set of allowed values checked at compile time (e.g. "known" | "again").
  2. What does as T after JSON.parse actually check?
    Nothing at runtime; it is a label telling the compiler to trust you.
  3. Why prefer setX(x => x + 1)?
    It uses the latest queued value, so rapid repeated updates are not lost.
  4. When does a useEffect cleanup run?
    Before the effect runs again (deps changed) and when the component unmounts.
  5. useRef vs useState?
    Both persist across renders; only state changes trigger a re-render.
  6. Why must providers that read other contexts be nested inside them?
    useContext only sees providers above it in the tree.
  7. Why must early returns come after all hooks?
    React matches hooks by call order; a conditional return before a hook changes the count between renders.
  8. Why does StrictMode double-run effects in development?
    To expose effects that don't clean up properly.
  9. Why is the swipe card keyed by id + ":" + pos?
    So undo, which shows the same question at a new position, mounts a fresh card that animates in.

Glossary

Assertion (as)
tells the compiler a type without checking.
Commit
React applying changes to the DOM.
Component
function returning JSX.
Context
value shared with a subtree via a provider.
Custom hook
a function starting with use that calls other hooks.
Dependency array
values an effect/memo/callback depends on.
Generic
a type parameter (T).
JSX
HTML-like syntax compiled to JS.
Key
stable identity for list items.
Literal type
a type whose only value is one specific string or number.
Non-null assertion (!)
claims a value is not null/undefined.
Props
a component's inputs.
Render
calling your component to get JSX.
StrictMode
dev-only checks that double-invoke effects.
Union type
a value that may be one of several types.
