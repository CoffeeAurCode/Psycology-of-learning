The problem this solves

Studying needs three gears:

  • Cards: self-graded recall.
  • Quiz: recognition with instant feedback, as on the exam.
  • List: lookup ("what was the answer about Maslow?").

All three filtered by week. And the chosen week should be shareable and bookmarkable: tapping "Week 3" on Home must open week 3.

3

Concepts

3.1 URL state vs stored preferences

State Where Why
Week (?week=3) URL query Shareable and bookmarkable; Home's week tiles link to it; the back button works
Mode (cards/quiz/list) localStorage (pol.studyMode) A personal preference: open Study tomorrow, get the same mode
Shuffle, hide mastered localStorage Preferences
Position in the deck component state Ephemeral

setParams(p, { replace: true }) updates the query without adding a history entry. Flipping through weeks shouldn't make "back" step through every week.

3.2 display: contents

An element with display: contents disappears from layout: its children behave as if they were children of its parent. We need one wrapper per question (to hold key, plus an optional week header and the card), but in the flex/grid "stack" each header and card should be a direct child. That is also what lets the week headers be sticky relative to the list.

3.3 Highlighting matches safely

Never inject user-typed text as HTML (innerHTML). That is an XSS hole (cross-site scripting: untrusted text executed as code). Split the string into before / match / after and render the match inside <mark> as React text. React escapes it.

Bug journal

Incident ticket · #01

Quiz mode shuffled twice on open; the first question swapped under your finger

Fixed
  1. Symptom
    The quiz test picked the correct answer for the first question and then saw a wrong mark. The screenshot showed the question "It is called extrinsic motivation if causal factor is ___", with B (social pressure) green and D (needs) red. The test had clicked D because it believed the question was a different one.
  2. Diagnosis
    We logged the question text the test read, then the text 600 ms later. They differed for the first question only. The original code was:
    TSX2 lines
    const [order, setOrder] = useState(() => shuffleArr(pool));   // shuffle #1 at mountuseEffect(() => restart(), [pool]);                            // shuffle #2 right after mount!
    Effects run after the first render, so restart(), meant for "the week changed", also ran on mount and reshuffled. The first question visibly changed a moment after appearing.
  3. Root cause
    An effect intended for changes also fires on mount. [pool] as a dependency means "run after mount and whenever pool changes".
  4. Fix
    Diff8 lines
     useEffect(() => restart(), [pool]); // reshuffle only when the week changes (not on mount, which would swap the first question) const lastPool = useRef(pool); useEffect(() => {   if (lastPool.current === pool) return;    // same pool as at mount → skip   lastPool.current = pool;   restart(); }, [pool]);
    (The expression-bodied effect was also an L2.05-style hazard; the braces remove it.)
  5. Lesson
    "Run when X changes" in React needs a guard against the mount run: store the previous value in a ref. And a human tapping fast would have hit this too. The test just tapped fast enough to prove it.

(A second, test-side issue on the same screen, where the test read the card that was sliding out, is told in L4.05.)

Flashcards

See all 7 cards as a listfor a quick scan
  1. Why is the week in the URL but the mode in storage?
    The week is shareable navigation state (deep links); the mode is a personal preference.
  2. What caused the quiz's first question to swap?
    An effect meant for pool changes also ran on mount and reshuffled.
  3. How do you run an effect only on changes, not on mount?
    Keep the previous value in a ref and skip when it's unchanged.
  4. What does a wrong quiz answer do besides scoring?
    Adds the card to missed and marks it "again" for flashcard review.
  5. Why highlight with slicing instead of innerHTML?
    React escapes text, so user input can't inject HTML (no XSS).
  6. What does display: contents do?
    Removes the wrapper's box so its children lay out as children of the parent.
  7. Why does the Study child remount on week change?
    key={mode + week} gives each week a fresh deck/quiz.
