L4.08

Ship it: deploy from Git and operate (+ Level 4 checkpoint)

Recipe card75 min
You need
L1.04 (Git, keys, static hosting), L2.04 (index.html, env variables), L3.05 (caching), L4.03 (the HTTP spec that checks all of this)
You'll produce
vercel.json, .gitignore, .vercelignore, .env.example, the SEO head of index.html, robots.txt, sitemap.xml, manifest.webmanifest, the Supabase dashboard settings, and the Level 4 checkpoint

In two sentences: Shipping this app means three systems agreeing: GitHub holds the code (and never the secrets), Vercel builds every push to main with the Vite preset and serves dist/ from its CDN with the right redirects, rewrites and cache headers, and Supabase holds the database and auth settings that no file in the repo can set by itself. This lesson walks every deployment file, the dashboard checklist, how to operate the site afterwards, and the two deploy bugs, both of which were silent misconfigurations rather than errors.

Session 2 update

In §4.7, the email rows (code templates, OTP length, SMTP) are history: email sign-in is off. The current Supabase and Google Cloud settings are in L2.07c §4, and the operating runbook for auth is in L4.09 §6.

By the end, without notes, you can

  1. Write vercel.json from memory and explain the redirect, the SPA rewrite and the cache header.
  2. Keep secrets out of Git and out of uploads: .gitignore, .vercelignore, .env.example, Vercel environment variables, and the build-time meaning of VITE_.
  3. Explain each SEO and sharing tag in index.html, plus robots, sitemap and manifest, and what the static fallback is for.
  4. Set up the Supabase side: run setup.sql, email templates with the code, OTP length, Site URL, SMTP.
  5. Operate it: deploy by pushing, preview branches, roll back, run test:prod, read analytics, and diagnose a deployment that "works" with the wrong settings.

2

The problem this solves

Deploying by hand ("run the CLI from my laptop") works once. It ties every release to one machine, one person and one folder, and that folder contains Supabase.txt with the secret key. It also leaves no record of which code is live.

The idea: deploy from Git. The repository is the single source of truth, a push to main is a release, any other branch gets a preview URL, and secrets live only in the hosts' settings.

3

Concepts

3.1 What a Vercel deployment is

Each deployment is an immutable snapshot: one build of one commit, at its own URL (psychology-of-learning-nptel-4iujqfk7j-….vercel.app). Domains are aliases pointing at a deployment. "Promoting" or a new production deployment only moves the alias; the old deployment still exists, which is why rollback is instant (point the alias back).

3.2 Framework presets

A preset tells Vercel how to build: for Vite, the build command is npm run build (here tsc -p . && vite build) and the output directory is dist. Without a preset ("Other"), Vercel may treat the repository as static files and serve the source index.html, which references /src/main.tsx, a file no browser can run: a blank page that returns 200 everywhere. That's the risk of §7.1.

3.3 Build-time environment variables

VITE_* variables are baked into the JavaScript at build time. So:

  • changing one in Vercel's settings does nothing until the next build (redeploy);
  • anything with the VITE_ prefix is public, by design. Only the URL and the publishable key may have it;
  • the secret key isn't needed by the site at all. It lives only in the test environment (SUPABASE_SECRET_KEY or the git-ignored Supabase.txt).

3.4 Redirects vs rewrites

Redirect Rewrite
What the browser sees A 301/308 response and a new URL in the address bar The original URL; the content comes from elsewhere
Used here for The short domain → the main domain Every path → index.html (the SPA)
Search engines Transfer ranking to the destination; treat it as one site See the URL as normal

308 is the "permanent, keep the method" redirect (permanent: true in vercel.json); 301 is the older permanent one. The HTTP spec accepts either.

Reading the real files

4.1 vercel.json (all of it)

JSON18 lines
{  "redirects": [    {      "source": "/:path*",      "has": [{ "type": "host", "value": "psychologyoflearning.vercel.app" }],      "destination": "https://psychology-of-learning-nptel.vercel.app/:path*",      "permanent": true    }  ],  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }],  "headers": [    {      "source": "/assets/(.*)",      "headers": [{ "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }]    }  ]}
  • The redirect: when the request's host is the short domain, send a permanent redirect to the same path on the main domain. :path* captures the whole path; Vercel keeps the query string, which the HTTP spec checks (/study?week=2 → …/study?week=2). One canonical domain means one set of search results and one origin for localStorage (progress saved on one domain isn't visible on another).
  • The rewrite: every path serves /index.html, so deep links and reloads (/study, /test/run) reach React Router. Real files in dist/ (assets, icons, robots.txt) are served first; the rewrite only applies when no file matches.
  • The header: everything under /assets/ (Vite's hashed files) is cacheable for a year and immutable (L3.05). Nothing else gets a long cache: index.html must always be fresh.

  • Why a second ignore file when deploys come from Git? A Git deployment only contains committed files, so the secrets can't be uploaded that way. Running and operating

  • Changing SQL: edit schema.sql / regenerate with npm run gen:sql, run npm run test:db, then paste setup.sql into the SQL editor. It's idempotent, so existing data survives (L4.02).

  • Search: add the site to Google Search Console and submit /sitemap.xml.
  • Signing out the CLI on a machine that shouldn't keep access: npx vercel logout.

Bug journal

Incident ticket · #01

Vercel built from Git with no framework set

Fixed
  1. Symptom
    Nothing visibly failed. After connecting the GitHub repository and starting a production deployment through the Vercel API, a check of the project's settings printed:
    Text1 line
    repo: CoffeeAurCode / Psycology-of-learning repoId: 1420670914 prodBranch: main framework: None
  2. Diagnosis
    The project had been created by the CLI, from a folder, and had never been given a framework preset. With "Other", Vercel could serve the repository as static files: the source index.html, whose module script points at /src/main.tsx. That page returns 200 for every URL and renders only the static fallback, so a status-code check would call it healthy.
  3. Root cause
    A deployment setting that defaults to "do something plausible" instead of failing. The CLI deploys had worked because they uploaded an already-built folder; Git deploys build on Vercel and need the preset.
  4. Fix
    Terminal4 lines
    # set the preset to Vite (build: npm run build, output: dist)npx -y vercel@64.2.0 api /v9/projects/psychology-of-learning-nptel -X PATCH \  --input fw.json    # {"framework":"vite","buildCommand":null,"outputDirectory":null,"installCommand":null}# → framework now: vite | nodeVersion: 24.x
    Then verify the artefact, not the status: the live HTML must reference a hashed bundle, not the source entry:
    Text2 lines
    $ curl -s https://psychology-of-learning-nptel.vercel.app/ | grep -oE '/assets/index-[A-Za-z0-9_-]+\.js'/assets/index-BfpkPwIX.js
    (The HTTP spec's "hashed assets are cached forever" test makes this check permanent: it fails if no /assets/index-*.js is found in the HTML.)
  5. Lesson
    After any change to how a site is built, check what is served (the hashed bundle), not only that it's served (200).
Incident ticket · #02

vercel link silently git-ignored .env.example

Fixed
  1. Symptom
    After vercel link, git status stopped listing .env.example as a file to commit, although .gitignore explicitly re-included it (!.env.example).
  2. Diagnosis
    The CLI had edited two files. It appended a token to .env.local (VERCEL_OIDC_TOKEN=…, checked with the values redacted: the Supabase settings had survived), and it appended to .gitignore:
    Text2 lines
    .vercel.env*
    git check-ignore .env.example confirmed the file was now ignored.
  3. Root cause
    In .gitignore, the last matching pattern wins. The appended .env* came after !.env.example, so it re-ignored the template.
  4. Fix
    Diff2 lines
    .vercel.env*
    then git check-ignore .env.example || echo ".env.example tracked OK" and git check-ignore -q .env.local && echo ".env.local ignored OK". Both printed OK. The existing .env and .env.* rules above already protect real env files.
  5. Lesson
    After any tool edits config files, read the diff (git diff .gitignore) and test the rule with git check-ignore, both for what must be ignored and for what must not.

Check yourself

Answer each one before you look. Multiple-choice questions mark your pick and let you try again; for open questions, answer aloud, then reveal and grade yourself honestly.

Q1
You change VITE_SUPABASE_ANON_KEY in Vercel's dashboard. When does the live site use the new key?
Did you have it?
After the next build. The value is inlined into the bundle at build time, so trigger a redeploy (push or "Redeploy").
Q2
Why does the redirect use the request's host, rather than a separate project for the short domain?
Did you have it?
Both domains are aliases of the same deployment. The has: host condition lets one config redirect only requests that arrive on the short domain.
Q3
Predict: a student bookmarks psychologyoflearning.vercel.app/study?week=2. What happens when they open it?
Did you have it?
A 308 to https://psychology-of-learning-nptel.vercel.app/study?week=2; the rewrite serves index.html; the router opens week 2. Their progress is in the main domain's localStorage.
Q4
A deployment returns 200 for / and every route, but the page is blank except for the plain week list. What do you check first?
Did you have it?
Whether the HTML references /src/main.tsx (source served: no framework preset or wrong output directory) or a hashed /assets/index-*.js. Then the browser console.
Q5
Why is .vercelignore needed if deploys come from Git?
Did you have it?
CLI deploys upload the working folder, including untracked secrets like Supabase.txt. .vercelignore protects that path; Git deploys only see committed files.
Q6
Students say "I never got the code". Name three causes in order of likelihood for this project.
Did you have it?
The built-in email rate limit (no custom SMTP yet); the email template still sends a link instead of {{ .Token }}; the email went to spam. (Check Supabase → Logs → Auth for each send.)

Practice

Easy10 min

Add security headers to vercel.json for every path: X-Content-Type-Options: nosniff, Referrer-Policy: strict-origin-when-cross-origin, and a Permissions-Policy that disables camera, microphone and geolocation. Extend the HTTP spec to check them on production.

Medium20 min

Add a Content-Security-Policy that allows only the site itself, the Supabase project URL (for connect-src) and Vercel's insights, and verify with the full UI suite that nothing breaks.

Hintreveal
The inline theme script in index.html needs either a hash in script-src or moving to a file. Start with Content-Security-Policy-Report-Only and read the console for violations.
Hard40 min

Make previews safe: point Preview deployments at a separate Supabase project (its own URL and publishable key in Vercel's Preview environment), with setup.sql applied, and run test:prod against a preview URL with BASE_URL. Done when a branch's preview never touches production data, and the live security tests pass against both.

12.1 Mixed quiz (interleaved across L4.01–L4.08)

C1. (L4.01) A data-test run says pass 5, skipped 12, fail 0. What do you conclude, and what do you check?

Answerreveal
The answer checks didn't run. Read the skip reasons; check the tool detection (ENOENT vs a non-zero exit status).

C2. (L4.02) Without grant all on all tables … to anon, authenticated, 16 of 19 DB tests fail. Why is "making them pass by accepting permission errors" wrong?

Answerreveal
The denials would come from privileges, not RLS, which isn't how production is protected; the tests would pass while proving nothing about the policies.

C3. (L4.03) An image check passes on status 200 but the image is missing. How, and what's the better assertion?

Answerreveal
The SPA rewrite serves index.html with 200 for any unknown path. Assert the content type (image/png|webp) or the body.

C4. (L4.04) A Playwright swipe works with a 100 ms pause before mouse.up() and fails without it, on WebKit. Mechanism and fix?

Answerreveal
Motion starts drags on an animation frame; all events arrived before one. Space the moves (16 ms apart) like a real finger.

C5. (L4.05) A quiz test chooses the "right" answer and the app marks it wrong, only sometimes. Name the two causes found.

Answerreveal
The app shuffled twice on mount (fixed in the app), and the test read the card that was sliding out (wait for the old text to be gone).

C6. (L4.06) A journey fails at submit only in full runs. What did the cleanup do, and what's the rule?

Answerreveal
Another file's afterAll deleted every e2e-bot- user, including one in use. Delete only what you created; sweep by pattern in global teardown.

C7. (L4.07) The app "freezes" after a swipe when checked by hand. Name two environment causes to rule out before debugging the app.

Answerreveal
A dev server reloading modules, and a background tab whose animation frames and timers are throttled. Test the production build headlessly.

C8. (L4.08) The live site returns 200 everywhere but shows only a plain list. Most likely cause?

Answerreveal
Source files served instead of the build (no framework preset): the HTML points at /src/main.tsx.

Flashcards

See all 12 cards as a listfor a quick scan
  1. What does the `vercel.json` redirect do?
    Requests on the short domain get a permanent (308) redirect to the same path on the main domain.
  2. Why the SPA rewrite?
    So deep links and reloads serve index.html and React Router handles the path.
  3. What gets immutable caching?
    Only /assets/*, Vite's hashed files.
  4. When do VITE_ env changes take effect?
    At the next build; they're inlined into the bundle.
  5. Why .vercelignore in a Git-deployed project?
    CLI deploys upload the working folder, including untracked secrets.
  6. Which .gitignore pattern wins?
    The last one that matches.
  7. What did vercel link add to .gitignore, and the effect?
    .env* after !.env.example, re-ignoring the template.
  8. Risk of no framework preset?
    Source files served (HTML pointing at /src/main.tsx), 200 everywhere, app never runs.
  9. How to verify a deploy beyond status codes?
    The HTML references a hashed /assets/index-*.js; then npm run test:prod.
  10. Supabase settings the repo can't set?
    Running setup.sql, email templates with {{ .Token }}, OTP length, Site URL, SMTP.
  11. Why is /me not in the sitemap?
    It's the account page; nothing worth indexing.
  12. What is a maskable icon?
    An icon with safe padding so the OS can crop it to its own shape.

Glossary

Alias (Vercel)
a domain pointing at a deployment.
Canonical URL
the preferred address of a page for search engines.
CDN
servers near users that cache and deliver files.
Framework preset
Vercel's build settings for a framework.
JSON-LD
structured data in a <script type="application/ld+json">.
Maskable icon
an icon designed to be cropped by the OS.
Open Graph
meta tags that control link previews.
Preview deployment
a deployment of a non-production branch at its own URL.
Rewrite
serving content from another path without changing the URL.
Rollback
pointing production back at an earlier deployment.
SMTP
the protocol for sending email.
Web app manifest
JSON describing an installable web app.
