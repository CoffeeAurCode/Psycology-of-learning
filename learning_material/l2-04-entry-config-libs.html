2

The problem this solves

Three boot-time problems would hurt every visit if left unsolved:

  1. Theme flash. React loads after the HTML, so a dark-mode user would see a light page for a split second.
  2. Blank page for crawlers and slow networks. An SPA's HTML is empty until JS runs.
  3. Crashes from the environment. Storage blocked, Supabase not configured, unknown errors shown raw.
3

Concepts

3.1 Theme before paint

The browser parses <head> top to bottom, and a plain (non-module) <script> there runs immediately, before the body is painted. So a short inline script can read the saved preference and set data-theme on <html> before any pixel shows. The CSS rules from L1.02 §4.1 then apply on the very first paint. React's ThemeProvider takes over later and keeps it in sync.

3.2 Vendor chunks and caching

Vite bundles everything into JS files with content hashes in their names (react-efav6phX.js). Same content, same name, so the browser can cache it forever (L4.08 sets immutable). If everything were in one file, changing one line of our code would change the hash of the whole 660 KB bundle, and every visitor would download React again. Splitting libraries into their own chunks means a deploy usually changes only our ~90 KB chunk:

Chunk Size (gzip) Changes when
index-*.js (our code) ~28 KB every deploy
react-*.js (React, React DOM, Router) ~72 KB React upgrade
supabase-*.js ~58 KB Supabase upgrade
motion-*.js ~42 KB Motion upgrade

3.3 Fisher–Yates shuffle (used by flashcards and quiz)

Definition. Walk from the last index down. At each position i, pick a random index j∈{0,…,i} and swap.

Why it is uniform. Position n−1 receives each of the n elements with probability n1​. Given that, position n−2 receives each of the remaining n−1 with probability n−11​, and so on. A particular final order therefore has probability

P(order)=n1​⋅n−11​⋯11​=n!1​,

which is the same for all n! orders. So every order is equally likely.

The naive version is biased. arr.sort(() => Math.random() - 0.5) does not give 1/n!. Sort algorithms compare elements a varying number of times, and an inconsistent comparator skews the result. With n=3, swapping with a random index in 0..n-1 at every step makes 33=27 equally likely paths onto 3!=6 orders. 27 is not divisible by 6, so some orders must appear more often than others.

ordinal(n): the rule: 11th/12th/13th are special, and otherwise the last digit picks st/nd/rd.

n v = n%100 (v−20)%10 s[(v-20)%10] s[v] result
1 1 −9 undefined "st" 1st
2 2 −8 undefined "nd" 2nd
11 11 −9 undefined undefined 11th (s[0])
21 21 1 "st" — 21st
112 12 −8 undefined undefined 112th
23 23 3 "rd" — 23rd

Why it works: for v < 20, (v−20)%10 is negative (JS remainders keep the sign), so the first lookup is undefined and s[v] handles 1, 2 and 3 directly; 4–19 fall through to "th". For v ≥ 20, (v−20)%10 is the last digit.

Bug journal

Incident ticket · #01

The no-JS fallback was invisible in light mode

Fixed
  1. Symptom
    In a light-theme screenshot of the raw HTML, the fallback heading and text in #root couldn't be seen.
  2. Diagnosis
    The inline style on the fallback <main> set color: #f4eadb (cream), and the light theme's body background is #f6f0e6, almost the same colour.
  3. Root cause
    A hard-coded colour in a theme-aware page.
  4. Fix
    Diff2 lines
     <main style="… font-family: system-ui, sans-serif; color: #f4eadb"> <main style="… font-family: system-ui, sans-serif">   <!-- inherit the themed body colour -->
  5. Lesson
    In a themed app, never hard-code text colours outside the token system. Inherit, or use a token.

Flashcards

See all 9 cards as a listfor a quick scan
  1. How does the app avoid a theme flash?
    A classic inline script in <head> sets data-theme from storage before the body paints.
  2. Why put fallback HTML inside #root?
    Crawlers and slow connections see real content; React replaces it on mount.
  3. Why must og:image be absolute?
    Link-preview scrapers don't resolve relative URLs.
  4. What does manualChunks buy?
    Library code in separately hashed files, cached across deploys.
  5. Why is resolved computed, not stored?
    Derived state can't go out of sync with pref and the OS setting.
  6. What does detectSessionInUrl: false skip?
    Parsing magic-link tokens from the URL; we use OTP codes.
  7. Probability of any order under Fisher–Yates?
    1/n!.
  8. Which tsconfig flags make unused code fail the build?
    noUnusedLocals and noUnusedParameters.
  9. What does PostgREST error PGRST202 mean here?
    The function doesn't exist, so setup.sql hasn't been run.

Canonical URL

Chunk
one output JS file.
Classic script

Content hash
hash of a file's bytes in its name.
Derived state

JSON-LD
JSON structured data using schema.org terms.
