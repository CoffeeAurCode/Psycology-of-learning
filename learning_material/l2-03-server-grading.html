The problem this solves

L2.02 locked test_attempts against client writes and hid questions entirely. Now somebody has to write attempts and read the key, and only after checking who's asking and whether the request is legitimate. That somebody is a function that runs with the owner's rights but trusts nothing the caller says, except their answers.

Concepts new in this lesson

3.2 Arrays: array_agg, array_length, generate_subscripts

  • array_agg(id) turns rows into one array: {304,1201,7,…}.
  • array_length(arr, 1) is the length along dimension 1. Gotcha: for an empty array it returns NULL, not 0. Hence coalesce(array_length(p_answers, 1), 0).
  • generate_subscripts(arr, 1) yields the indexes 1, 2, …, n. Postgres arrays are 1-based. Our JS arrays are 0-based, but we only ever send whole arrays, so positions line up automatically.

3.3 Time: now() vs clock_timestamp()

now() is the start time of the current transaction. It stays constant inside it. clock_timestamp() is the actual current time. In submit_test the duration uses clock_timestamp(), the true moment of grading. (now() would differ only by milliseconds here, but clock_timestamp() states the intent.) The 3-hour expiry check uses now(), which is fine at that granularity.

3.4 Row locks: select … for update

for update locks the selected row until the transaction ends. If two submit_test calls for the same attempt arrive at once (a double tap, or two tabs), the second waits, then sees submitted_at is not null and fails with "already submitted". Without the lock, both could read "not submitted" and both could write, a race that could overwrite a score.

3.5 Grants on functions

New functions are executable by PUBLIC (everyone) by default, and Supabase also grants anon/authenticated execute on new objects. So we revoke first, then grant precisely:

Function anon authenticated Why
start_test ✗ ✓ Needs a user to own the attempt
submit_test ✗ ✓ Same
get_my_stats ✗ ✓ "My" makes no sense anonymously
get_leaderboard ✓ ✓ Public board: visitors see it before signing up

4.1 start_test (lines 80–116)

SQL37 lines
-- Start a ranked test: 100 random questions, start time stamped by the server.create or replace function public.start_test()returns jsonlanguage plpgsqlsecurity definerset search_path = publicas $$declare  uid     uuid := auth.uid();  qids    int[];  aid     uuid;  started timestamptz;begin  if uid is null then    raise exception 'Please sign in first' using errcode = '28000';  end if;  if not exists (select 1 from profiles where id = uid) then    raise exception 'Choose a display name first' using errcode = 'P0001';  end if;   -- one open attempt at a time; starting again abandons the previous one  delete from test_attempts where user_id = uid and submitted_at is null;   select array_agg(id) into qids  from (select id from questions order by random() limit 100) s;   if qids is null then    raise exception 'No questions in the database yet (run seed.sql)';  end if;   insert into test_attempts (user_id, question_ids, total)  values (uid, qids, array_length(qids, 1))  returning id, started_at into aid, started;   return json_build_object('attempt_id', aid, 'question_ids', qids, 'started_at', started);end;$$;

Line notes:

  • L3returns json: supabase-js receives it as a JS object in data.
  • L5security definer: runs as the owner (the role that ran setup.sql), which bypasses RLS on these tables. This is why it can insert into test_attempts.
  • L6set search_path = public: inside the function, unqualified names like profiles resolve only in public. Without it, a caller could create a look-alike object in a schema earlier on their path and hijack what the definer function calls (L3.01).
  • L9uid uuid := auth.uid(): read the caller's id once. Every later statement uses uid, never anything the caller passed.
  • L14Guard 1, uid is null: anonymous callers. (Grants already block anon; this is defence in depth.) errcode '28000' is Postgres's "invalid authorization" class.
  • Guard 2, profile exists: the leaderboard needs a display name. The app catches the message "Choose a display name first" and sends the user to pick one. Error code P0001 is the default for raise exception; written here for clarity.
  • L22delete … submitted_at is null: one open attempt per user. Tapping "Start over" abandons the old one. It also keeps the table small.
  • L25order by random() limit 100: a uniform random sample. Every one of the 130 questions has an equal chance. It sorts all rows by a random number, fine for 130 rows (L3.02 discusses scale).
  • L24array_agg(id) into qids: collects the sample into int[]. With zero questions (seed not run), array_agg returns NULL, hence the next guard.
  • total = array_length(qids, 1): 100 normally. If someone runs this with fewer questions seeded, the score is out of what was actually drawn.
  • L33returning … into aid, started: the generated uuid and the default now() come back without a second query.
  • L33, 35The returned started_at is informational. The client shows its own timer from Date.now() because phone and server clocks differ.

4.2 get_leaderboard (lines 118–155)

SQL38 lines
-- Leaderboard: each player's best attempt (highest score, then fastest).create or replace function public.get_leaderboard(p_limit int default 100)returns table (  rank         bigint,  user_id      uuid,  display_name text,  score        int,  total        int,  duration_ms  int,  attempts     bigint,  submitted_at timestamptz)language sqlstablesecurity definerset search_path = publicas $$  with best as (    select distinct on (t.user_id)           t.user_id, t.score, t.total, t.duration_ms, t.submitted_at    from test_attempts t    where t.submitted_at is not null    order by t.user_id, t.score desc, t.duration_ms asc, t.submitted_at asc  ),  counts as (    select t.user_id, count(*) as attempts    from test_attempts t    where t.submitted_at is not null    group by t.user_id  )  select rank() over (order by b.score desc, b.duration_ms asc) as rank,         b.user_id, p.display_name, b.score, b.total, b.duration_ms, c.attempts, b.submitted_at  from best b  join profiles p on p.id = b.user_id  join counts  c on c.user_id = b.user_id  order by rank, b.submitted_at  limit least(greatest(coalesce(p_limit, 100), 1), 100000);$$;

Line notes:

  • L3returns table (…): callers can select … from get_leaderboard(10), and supabase-js rpc("get_leaderboard", { p_limit: 200 }) gets an array of rows. rank() produces bigint, count(*) too, hence those column types.
  • L18with best as (…): a CTE (common table expression), a named sub-query used below.
  • L19, 23distinct on (t.user_id) + order by t.user_id, t.score desc, t.duration_ms asc, t.submitted_at asc: keep one row per user, the first in that order. So the best attempt is: highest score, then fastest, then earliest (a deterministic tie-break). distinct on requires the order by to start with the same column.
  • L25, 35counts: total submitted attempts per user, shown as "3 attempts".
  • L31rank() over (order by b.score desc, b.duration_ms asc): a window function. Equal score and time share a rank (1, 1, 3…). Frame-by-frame in L3.02.
  • L34join profiles: users without a profile never appear. In practice they can't start tests anyway (guard 2).
  • L36order by rank, b.submitted_at: stable display order within ties.
  • L37limit least(greatest(coalesce(p_limit, 100), 1), 100000): clamp the caller's limit to between 1 and 100,000. coalesce handles null, greatest(…,1) stops limit -5, and least(…,100000) stops someone requesting a billion rows. The PGlite test "leaderboard limit is clamped" calls it with -5 and 2.
  • Note what is not returned: emails, attempt ids, answers. The leaderboard is public (granted to anon), so it returns only what a public board shows.

4.3 submit_test (lines 157–210)

SQL54 lines
-- Submit answers; graded here against the server-side key.-- p_answers[i] is the chosen option for question_ids[i], or -1 if skipped.create or replace function public.submit_test(p_attempt uuid, p_answers int[])returns jsonlanguage plpgsqlsecurity definerset search_path = publicas $$declare  a       test_attempts;  s       int;  correct int[];  dur     int;  my_rank bigint;  players bigint;begin  select * into a from test_attempts  where id = p_attempt and user_id = auth.uid()  for update;   if not found then    raise exception 'Test attempt not found';  end if;  if a.submitted_at is not null then    raise exception 'This test was already submitted';  end if;  if now() - a.started_at > interval '3 hours' then    raise exception 'This test expired (3 hour limit). Start a new one.';  end if;  if coalesce(array_length(p_answers, 1), 0) <> array_length(a.question_ids, 1) then    raise exception 'Answer count does not match';  end if;   select coalesce(sum(case when p_answers[i] = q.answer then 1 else 0 end), 0)::int,         array_agg(q.answer order by i)    into s, correct  from generate_subscripts(a.question_ids, 1) as i  join questions q on q.id = a.question_ids[i];   dur := (extract(epoch from (clock_timestamp() - a.started_at)) * 1000)::int;   update test_attempts     set submitted_at = now(), answers = p_answers, score = s, duration_ms = dur   where id = a.id;   select l.rank into my_rank from get_leaderboard(100000) l where l.user_id = auth.uid();  select count(distinct t.user_id) into players from test_attempts t where t.submitted_at is not null;   return json_build_object(    'score', s, 'total', a.total, 'duration_ms', dur,    'correct', correct, 'rank', my_rank, 'players', players  );end;$$;

Line notes:

  • L10a test_attempts;: a row-type variable; a.started_at, a.question_ids and so on are its fields.
  • L18where id = p_attempt and user_id = auth.uid(): ownership is part of the lookup. Someone else's attempt id isn't found, so we don't even reveal that it exists. The error is the same "not found" either way.
  • L19for update: the row lock from §3.4.
  • Four guards, each a specific message the app shows in the submit sheet:
    1. not found (wrong id, or not yours),
    2. already submitted (double tap or replay),
    3. expired (> 3 h), which stops "start, look up answers all day, submit",
    4. answer count ≠ question count, which stops sending 3 answers and having the rest scored somehow.
  • The grading query. For each index i, join the question with id question_ids[i], and add 1 when p_answers[i] = q.answer. Skipped answers are -1 and never equal a real index. coalesce(…, 0) handles the impossible-but-safe "no rows" case. ::int because sum returns bigint.
  • L35array_agg(q.answer order by i): the correct answers in test order, returned so the results page can show "your answer vs correct" without the client ever having had the key during the test.
  • L13, 40, 43, 50dur: clock_timestamp() - started_at is an interval. extract(epoch from …) gives seconds (with fractions), * 1000 gives milliseconds, and ::int rounds. An int holds about 24.8 days of milliseconds, far more than the 3-hour limit.
  • L19, 42update … where id = a.id: fill the four "open" columns once.
  • Rank lookup: call our own leaderboard with a large limit and pick our row. Here the limit was a bug, caught before shipping (incident below).
  • L15, 47, 51players: count of distinct users with a submitted attempt. Shown as "of 41 players".

4.4 get_my_stats (lines 212–228)

SQL16 lines
create or replace function public.get_my_stats()returns jsonlanguage sqlstablesecurity definerset search_path = publicas $$  select json_build_object(    'best_score',    (select l.score       from get_leaderboard(100000) l where l.user_id = auth.uid()),    'best_total',    (select l.total       from get_leaderboard(100000) l where l.user_id = auth.uid()),    'best_duration', (select l.duration_ms from get_leaderboard(100000) l where l.user_id = auth.uid()),    'rank',          (select l.rank        from get_leaderboard(100000) l where l.user_id = auth.uid()),    'attempts',      (select count(*) from test_attempts t where t.user_id = auth.uid() and t.submitted_at is not null),    'players',       (select count(distinct t.user_id) from test_attempts t where t.submitted_at is not null)  );$$;
  • Powers the three Home stat tiles. A user with no attempts gets nulls, and the UI shows "–".
  • Honest critique: it calls get_leaderboard four times. Correct, but it computes the whole board four times per Home visit. That's fine for hundreds of players, wasteful for tens of thousands. L3.02 rewrites it as one lateral lookup.

4.5 The grants (lines 230–238)

SQL8 lines
revoke all on function public.start_test()                from public, anon;revoke all on function public.submit_test(uuid, int[])    from public, anon;revoke all on function public.get_my_stats()              from public, anon;revoke all on function public.get_leaderboard(int)        from public;grant execute on function public.start_test()             to authenticated;grant execute on function public.submit_test(uuid, int[]) to authenticated;grant execute on function public.get_my_stats()           to authenticated;grant execute on function public.get_leaderboard(int)     to anon, authenticated;
  • Functions are identified by name and argument types (submit_test(uuid, int[])), because Postgres allows overloads.
  • from public removes the default execute-for-everyone. from anon removes Supabase's default grant.
  • Result: an anonymous rpc("start_test") fails with 42501 permission denied for function start_test. The live test asserts exactly that code.

Bug journal

Incident ticket · #01

Rank lookup capped at 1,000 players (caught before shipping)

Caught early
  1. Symptom
    None yet in production. Found while re-reading the first draft: get_leaderboard clamped p_limit to at most 1000, while submit_test and get_my_stats call get_leaderboard(100000) and search for the caller's row.
  2. Diagnosis
    Traced it with a thought experiment: player #1,001 submits, the inner call returns only 1,000 rows, their row isn't among them, so my_rank is NULL and the results page shows "–" instead of "1001st".
  3. Root cause
    One limit was serving two purposes: protecting the public endpoint from huge responses, and an internal "give me everyone" lookup.
  4. Fix
    Diff2 lines
      limit least(greatest(coalesce(p_limit, 100), 1), 1000);  limit least(greatest(coalesce(p_limit, 100), 1), 100000);   -- internal rank lookups need the full board
  5. Lesson
    When a function both serves the public and is reused internally, check every caller's assumptions about its limits. The cleaner design (in L3.02) looks up one user's rank directly, with no limit involved.

Flashcards

See all 9 cards as a listfor a quick scan
  1. Which two values does the client control in a ranked test?
    The decision to start, and the array of chosen options.
  2. Why set search_path = public?
    So a definer function can't be tricked into resolving names to attacker-created objects in another schema.
  3. Why for update in submit?
    Locks the attempt row so concurrent submissions serialise; the second sees it already submitted.
  4. What does array_length return for an empty array?
    NULL. Hence coalesce(…, 0).
  5. How is a skipped answer encoded?
    -1, which never equals a valid 0-based index.
  6. What does distinct on (user_id) keep?
    The first row per user in the order by, here the best attempt (score desc, duration asc, earliest).
  7. Which functions can anon execute?
    Only get_leaderboard.
  8. Why is the rank lookup limit 100,000?
    A cap of 1,000 would make ranks beyond 1,000 come back NULL.
  9. Why clock_timestamp() for the duration?
    It is the real current time; now() is frozen at transaction start.
