The problem this solves

Every page needs the same frame: providers above it, a top bar, a tab bar, transitions between pages, a safety net for crashes, and a pleasant first load. Putting that once in a "shell" keeps the pages focused on their own job.

3.2 Motion: AnimatePresence, keys and layoutId

Definition. Motion (formerly Framer Motion) animates React components declaratively: initial (start), animate (target) and exit (on removal).

The problem it solves. React removes a component from the DOM immediately when it stops rendering, so there is no chance to animate it out. <AnimatePresence> keeps a removed child mounted until its exit animation finishes.

layoutId. Two elements with the same layoutId (even in different components, or the same one moving) are treated as one element. When it re-renders somewhere else, Motion animates it from the old position to the new one. Only the active tab renders <motion.span layoutId="tab-pill">, so switching tabs makes the pill glide.

MotionConfig reducedMotion="user". If the OS asks for reduced motion, Motion skips transform animations app-wide. The CSS does the same for CSS animations (L2.10b).

3.3 Error boundaries

Definition. A class component with static getDerivedStateFromError that catches errors thrown while rendering its children, and renders a fallback instead of letting React unmount the whole app.

It does not catch errors in event handlers, in async code (promises, setTimeout), or in itself. React 19 removes the whole tree on an uncaught render error. That is the blank page we saw.

// Splash only on the first load of a browser session, and never longer than needed.const firstLoad = (() => {  try {    if (sessionStorage.getItem("pol.splashed")) return false;    sessionStorage.setItem("pol.splashed", "1");  } catch {    /* ignore */  }  return true;})(); function Shell() {  const { ready } = useAuth();  const { pathname } = useLocation();  const running = pathname.startsWith("/test/run");  const [phase, setPhase] = useState<"show" | "fade" | "gone">(firstLoad ?   • firstLoad is computed once per module load (an IIFE, an immediately-invoked function). sessionStorage lives per tab, so reloads in the same tab skip the splash and a new tab shows it once.
  • minDone (650 ms minimum): a splash that flashes for 50 ms looks like a glitch.
  • ready comes from AuthProvider: the stored session has been read, so the first real screen won't flicker between signed-out and signed-in.
  • The cap: whatever happens, the splash is gone after 4 s.
  • fade is a CSS transition (.splash.fading { opacity: 0 }), and gone unmounts after a plain timer. That design is the fix for incident 2.

Bug journal

Incident ticket · #01

Blank page: destroy is not a function

Fixed
  1. Symptom
    The first browser run showed a dark, empty page. Console:
    Text5 lines
    %s must not return anything besides a function, which is used for clean-up.%s useEffectIt looks like you wrote useEffect(async () => ...) or returned a Promise. …TypeError: destroy is not a function    at commitHookEffectListUnmount (react-dom_client.js:9449)An error occurred in the <AnimatedRoutes> component.
  2. Diagnosis
    React said an effect returned something other than a cleanup. None of our effects were async. We searched for concise-arrow effects with a regex: useEffect\(\(\) => [^{]. Seven matches; most called save() (returns undefined) or build(). The suspicious one was useEffect(() => window.scrollTo({ top: 0 }), [location.pathname]) in AnimatedRoutes, which was also the component named in the warning. Checking in the page: String(window.scrollTo({top:0})) returned "[object Promise]". In this Chrome version, scrollTo returns a Promise.
  3. Root cause
    A concise arrow returns its expression. React stored the Promise as the effect's "cleanup", and on the next path change tried to call it: destroy is not a function. The error happened during commit, so React 19 unmounted the whole tree, and the page went blank.
  4. Fix
    Diff4 lines
     useEffect(() => window.scrollTo({ top: 0 }), [location.pathname]); useEffect(() => {   window.scrollTo({ top: 0 });          // braces: the effect returns undefined }, [location.pathname]);
    We applied the same change to all seven expression-bodied effects, so no future API change in save() or build() can repeat it.
  5. Lesson
    Never use a concise arrow for useEffect; always use braces. Even a function that "returns nothing" today may return a Promise tomorrow. The lint rule react-hooks/exhaustive-deps won't catch this, but a simple grep for useEffect(() => [^{] will.
Incident ticket · #02

The splash never disappears (headless and background tabs)

Fixed
  1. Symptom
    In headless screenshots, four of five pages were still covered by the splash after 20 seconds of simulated time. In a background Chrome tab, the same.
  2. Diagnosis
    Was auth stuck? --dump-dom showed the Test page content ("Sign in with email to start") under the splash, so ready was true. The splash element had style="opacity: 1", so its exit animation had never run. The first version used <AnimatePresence>{!(ready && minDone) && <Splash/>}</AnimatePresence> with a Motion exit={{ opacity: 0 }}. AnimatePresence only removes a child after its exit animation finishes, and in background tabs (where requestAnimationFrame pauses) and some headless modes, that never happened.
  3. Root cause
    Unmounting depended on an animation-completion event that the environment doesn't guarantee.
  4. Fix
    A 3-phase state machine driven by timers. fade sets a CSS class with transition: opacity .4s; gone unmounts after 450 ms via setTimeout, and a 4 s cap forces gone regardless. Shown once per tab (sessionStorage).
    Diff2 lines
     <AnimatePresence>{!(ready && minDone) && <Splash key="splash" />}</AnimatePresence> {phase !== "gone" && <Splash fading={phase === "fade"} />}
  5. Lesson
    Anything that blocks the UI must have a timeout that doesn't depend on animations, network or other events. Decorative animation can be best-effort; access to the app cannot.

Flashcards

See all 8 cards as a listfor a quick scan
  1. What does AnimatePresence add that React lacks?
    It keeps removed children mounted until their exit animation finishes.
  2. What does mode="wait" do?
    Mounts the next keyed child only after the previous one finished exiting.
  3. How does the tab pill glide between tabs?
    A shared layoutId; Motion animates the single element to its new position.
  4. Why did the page go blank on first run?
    useEffect(() => window.scrollTo(...)) returned a Promise; React called it as cleanup → destroy is not a function.
  5. Why must blocking UI never wait on an animation event?
    Hidden tabs and headless browsers may never fire it; the UI would stay blocked.
  6. What does an error boundary not catch?
    Errors in event handlers, async code, and the boundary itself.
  7. Why key the boundary by pathname?
    Navigating remounts it, clearing the error state.
  8. Why is the TopBar's scroll listener passive?
    It promises not to preventDefault, letting the browser scroll without waiting.
