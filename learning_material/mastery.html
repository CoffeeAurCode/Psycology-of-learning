The rebuild challenge

Rules. An editor and a terminal. You may read error messages and --help output. You may not open this series, the original repository, documentation sites or an AI assistant. Use a new empty folder.

Time box. The checkpoint itself is three 60-minute sittings (one per block below). The full rebuild, every file of the app, takes most learners 2–4 days of focused work; do it once, after the checkpoint, as the ultimate test.

Sitting Task (from the mastery spec in the outline) Passing bar
A · Data and database (60 min) 1. Write the extraction plan for the PDFs and the shape of questions.json (ids week*100 + n, 0-based answers), and scripts/gen-seed.mjs that writes seed.sql/setup.sql. 2. Write supabase/schema.sql from a blank file: 4 tables, RLS on all, the 8 policies, the 4 functions with security definer, search_path and grants. The original repository's npm run test:unit and npm run test:db pass when your schema.sql (concatenated with the real seed.sql as setup.sql) replaces theirs. Explain in one paragraph why a student can't forge a score.
B · The app (70 min) 3. Scaffold Vite + React + TypeScript by hand. 4. Write the shell (providers, router, transitions, tab bar/rail, splash, error boundary). 5. Write Google sign-in (SignIn, the two client options) and the name step, and list the nine dashboard settings in order. 6. Write the SwipeCard with swipe thresholds and the angle-driven flip. 7. Write the runner's state: attempt in storage, auto-advance, flags, resume, submit. 8. Write the token block, the deck's height formula and the side-rail override. npx tsc -p . --noEmit passes on what you wrote. The self-check lists in §2 for B are all ticked.
C · Test and ship (65 min) 9. Write playwright.config.ts, the support helpers, one test from each of: data, DB, UI (with a transition), live security, a11y. 10. Write vercel.json, the ignore files, and the Supabase checklist. 11. Diagnose the 21 symptoms in §4 without looking anything up. 12. Write the Google hand-off test and the five incident probes. Your config lists all 12 projects with the right testMatch; your UI test waits for a state, never a fixed sleep for state; ≥ 18 of 21 diagnoses correct; your hand-off test intercepts /auth/v1/authorize before the click.

The full rebuild's acceptance test. Copy the original repository's tests/ folder into your rebuild. Your rebuild passes: npm run test:unit (17), npm run test:db (19), and npx playwright test --project=api --project=pixel-7 --project=iphone-se --project=laptop-chrome-1366. Class names, accessible names and storage keys are part of the contract the tests check, which is exactly why you had to learn them.

Debug from memory

Each symptom is real (from this build) or a verified failure mode of the stack. Name the cause and the fix before opening the answer.

Answer each one before you look. Multiple-choice questions mark your pick and let you try again; for open questions, answer aloud, then reveal and grade yourself honestly.

D1
First run in the browser: a blank page and TypeError: destroy is not a function.
Did you have it?
An effect written as a concise arrow returned window.scrollTo(...)'s Promise; React called it as cleanup. Use braces (L2.05).
D2
(session 1, email codes) Nobody can sign in: every real email code is rejected.
Did you have it?
The project sends 8-digit codes; the app cut input to 6. Accept 6–10 (L2.07a).
D3
On iPhones the card shows the answer mirrored before you flip it.
Did you have it?
WebKit didn't honour backface-visibility in that nesting; drive face opacity from the angle (L2.08a).
D4
A sideways swipe takes the browser back to the previous page.
Did you have it?
Chrome's overscroll history navigation; overscroll-behavior-x: none on html (L2.08a).
D5
Swipes work with a mouse but not with a finger on the options area.
Did you have it?
The scroll container claimed the touch gesture; touch-action: pan-y on .fc-scroll (L2.08a, L2.10b).
D6
Signing out turns the whole app into a blank page.
Did you have it?
AnimatePresence kept the exiting <Me/> mounted for its fade, it re-rendered after profile was cleared, and profile!.display_name threw. Guard after the hooks, clear session and profile together, and add an error boundary (L2.07b).
D7
iPhones can pan the page sideways for a moment when a screen slides in.
Did you have it?
A transformed child extends the scrollable area; overflow-x: clip must be on html (and body), not only body (L2.10a).
D8
On the iPhone SE the "Got it" button sits under the tab bar.
Did you have it?
The deck's 340 px minimum made the page too tall; short-screen tiers with measured constants (L2.10c).
D9
The quiz marks your correct tap as wrong, now and then, right after opening.
Did you have it?
It shuffled twice on mount, replacing the first question; reshuffle only when the pool changes (L2.08b).
D10
Tab labels fail axe contrast only on some phones.
Did you have it?
The 86% translucent bar composited over the dark hero; 95% and a darker --tab-ink (L3.04).
D11
Mobile Lighthouse performance 81 with TBT 0 ms.
Did you have it?
A render-blocking third-party font stylesheet and oversized PNG logos; self-host the font, WebP at display size, width/height (L3.05).
D12
The data tests report fail 0 but skipped 12.
Did you have it?
pdftotext -v exits 99; the detection treated any error as "missing". Check ENOENT (L4.01).
D13
An image test passes on status 200 but the image is missing in production.
Did you have it?
The SPA rewrite serves index.html for missing files, and the spec defaulted to production where the file wasn't deployed. Check content types; one base URL (L4.03).
D14
A Playwright swipe does nothing in WebKit, only in automation.
Did you have it?
All moves and the pointerup landed before an animation frame, so the drag never started; pace moves 16 ms apart (L4.04).
D15
The signed-in journey fails at submit only when the full suite runs.
Did you have it?
Another worker's cleanup deleted every e2e-bot- user; delete only your own (L4.06).
D16
git status stopped showing .env.example after linking the Vercel project.
Did you have it?
vercel link appended .env* after !.env.example; the last pattern wins (L4.08).
D17
A friend's sign-up shows HTTP 504. Health, settings and REST all answer 200 in under a second.
Did you have it?
Custom SMTP pointed at the website (…vercel.app:465); the connection hangs because packets are dropped, so the gateway times out. Fix SMTP with a real provider, or remove email sign-in (L3.06).
D18
Google Cloud rejects vercel.app in Authorised domains: "Invalid domain: must be a top private domain".
Did you have it?
vercel.app (like supabase.co) is on the Public Suffix List. Add the full hostnames psychology-of-learning-nptel.vercel.app and <ref>.supabase.co (L2.07c, L3.06).
D19
Back from Google on /me?next=%2Ftest&code=…, the student still sees "Continue with Google".
Did you have it?
Nothing exchanged the code: detectSessionInUrl is false. If it's true, the flow finished in a different browser or tab whose storage lacks the matching verifier (L2.07c, L3.06).
D20
Google sign-in works, but every student lands on the home page instead of the test.
Did you have it?
redirect_to isn't in the Supabase Redirect URLs allow-list, so Supabase falls back to the Site URL. Add https://…vercel.app/** (L2.07c).
D21
The Email provider was just switched off. A teammate starts rewriting the test helpers "because admin-minted codes won't work now". What do you do first, and what happens?
Did you have it?
Run api-security.spec.ts first. It passes (13/13): the switch closes the public email path (422 email_provider_disabled), but admin-minted codes still verify. No rewrite needed (L4.09).

Master deck

Every flashcard from every lesson, in course order. Go through all of them in one sitting the first time (≈ 3 minutes per lesson); afterwards, review only the ones you missed. Keep this deck's schedule separate from the lessons' (it's your exam deck).

366 cards from 38 lessons. Answer each card aloud before you reveal it, then grade yourself honestly. Filter by lesson to drill one part of the course; the list underneath shows every card in course order.

See all 366 cards as a listfor a quick scan
  1. Why does the server, not the browser, compute the score?
    Anything in the browser can be changed by the user. The answer key and the grading live in Postgres, where the client cannot read the key or write attempts directly.
  2. Which two tables can a signed-in user write directly?
    profiles (own row) and card_progress (own rows). test_attempts is written only by functions; questions by nobody from the browser.
  3. What makes the ranked time cheat-proof?
    It is now() − started_at, both on the database server's clock.
  4. What does the publishable key let a stranger do?
    Only what RLS and grants allow anonymous users: read the leaderboard function and attempt sign-in. Nothing private.
  5. How many questions are in the pool, and how many in a test?
    130 in the pool (weeks 0–12 × 10); each test draws 100 at random on the server.
  6. How does the app get deployed now?
    git push to main; Vercel's Git integration builds with Vite and publishes.
  7. On a laptop, where does the tab bar go?
    It becomes a fixed side rail (≥ 1024 px), restyled by responsive.css.
  8. What is the ranking rule?
    Each player's best attempt; higher score first; ties broken by shorter duration.
  9. What does viewport-fit=cover oblige you to do in CSS?
    Pad content with env(safe-area-inset-*) so it stays out of the notch and home-indicator areas.
  10. Why are dark tokens written twice in our CSS?
    Once under prefers-color-scheme: dark for "auto" (unless the user forced light), once under [data-theme="dark"] for an explicit dark choice.
  11. What must a useEffect callback return?
    Nothing, or a cleanup function. Never a Promise or any other value.
  12. What does pointercancel mean for a swipe?
    The browser took over the gesture (usually to scroll); the page gets no further moves or pointerup.
  13. Why wrap localStorage in try/catch?
    It can throw in private modes, when full, or when blocked. Crashing on load is worse than losing persistence.
  14. Why does an SPA host need a catch-all rewrite?
    Direct visits or refreshes of client routes reach the server, which has no such file; the rewrite serves index.html so the router can render the route.
  15. When is Cache-Control: immutable safe?
    When the filename changes with the content (hashed build assets), so a new version always has a new URL.
  16. Why can overflow: hidden on an ancestor break position: sticky?
    It makes that ancestor a scroll container; sticky then sticks relative to it, not the viewport.
  17. What does a string-literal union type give you?
    A closed set of allowed values checked at compile time (e.g. "known" | "again").
  18. What does as T after JSON.parse actually check?
    Nothing at runtime; it is a label telling the compiler to trust you.
  19. Why prefer setX(x => x + 1)?
    It uses the latest queued value, so rapid repeated updates are not lost.
  20. When does a useEffect cleanup run?
    Before the effect runs again (deps changed) and when the component unmounts.
  21. useRef vs useState?
    Both persist across renders; only state changes trigger a re-render.
  22. Why must providers that read other contexts be nested inside them?
    useContext only sees providers above it in the tree.
  23. Why must early returns come after all hooks?
    React matches hooks by call order; a conditional return before a hook changes the count between renders.
  24. Why does StrictMode double-run effects in development?
    To expose effects that don't clean up properly.
  25. Why is the swipe card keyed by id + ":" + pos?
    So undo, which shows the same question at a new position, mounts a fresh card that animates in.
  26. RLS enabled, no policies: what can users read?
    Nothing: zero rows (writes rejected).
  27. using vs with check?
    using filters existing rows (select/update/delete); with check validates new or updated rows (insert/update).
  28. What does auth.uid() return for anonymous requests?
    null, so auth.uid() = user_id is never true.
  29. Why security definer for submit_test?
    It must read the answer key and write attempts that the caller cannot; it runs with the owner's rights and checks the caller itself.
  30. Why set search_path = public on definer functions?
    So object names resolve only in public, preventing hijacking via look-alike objects in another schema.
  31. Is a JWT secret?
    No, it is signed, not encrypted. The payload is readable by anyone.
  32. Which Supabase key bypasses RLS?
    The secret / service-role key. Never ship it to a browser.
  33. Why the VITE_ prefix?
    Only prefixed variables are exposed to client code, so other secrets aren't bundled by accident.
  34. Error codes 23505 and 23514?
    Unique violation; check-constraint violation.
  35. What does npm run build do before bundling, in this project?
    Runs tsc -p . to type-check; any error fails the build.
  36. Why "type": "module" in package.json?
    So JS/TS config files are ES modules and can use import.
  37. Why verbatimModuleSyntax?
    Forces import type for type-only imports so per-file compilation (Vite) never imports a non-existent runtime value.
  38. Where does index.html live in a Vite app?
    The project root; it is the entry point.
  39. Why test with preview before deploying?
    It serves the production build; some bugs exist only after bundling or without the dev server.
  40. How do you wrap an index backwards safely?
    (p + d + len) % len, because JS % keeps the sign.
  41. What is the id of week 12, question 1?
    1201 (100·12 + 1).
  42. Why not sequential ids?
    Inserting a question would shift later ids and corrupt saved progress and attempts.
  43. How do you escape a quote inside a SQL string?
    Double it: ''.
  44. Why new URL(path, import.meta.url) in a Node script?
    Resolves relative to the script file, independent of the working directory.
  45. Why does the seed use on conflict do update?
    Idempotent: you can re-run it after fixing data.
  46. Which part of a contradictory key did we trust, and how is it recorded?
    The answer text; recorded as answer: 3 plus a note on the question.
  47. What catches "edited JSON, forgot gen:sql"?
    The unit test "supabase/seed.sql is in sync with questions.json".
  48. Why BY_ID?
    O(1) lookup of questions by the ids the server sends.
  49. Why no policies on questions?
    So no client can read or write the answer key; only definer functions use it.
  50. Why only a select policy on test_attempts?
    Writes must go through start_test/submit_test so score and time are computed by the server.
  51. Why drop policy if exists before create policy?
    Postgres has no create or replace policy; this makes the script re-runnable and updates the rule.
  52. What does the partial index cover?
    Only submitted attempts, ordered by score desc, duration asc: the leaderboard's shape.
  53. How are names unique ignoring case?
    A unique expression index on lower(display_name).
  54. What happens to a user's rows when the user is deleted?
    on delete cascade removes their profile, attempts and progress.
  55. RLS-denied delete: error or nothing?
    Nothing: 0 rows affected, no error.
  56. Does create table if not exists add new columns?
    No; use alter table … add column if not exists.
  57. Which two values does the client control in a ranked test?
    The decision to start, and the array of chosen options.
  58. Why set search_path = public?
    So a definer function can't be tricked into resolving names to attacker-created objects in another schema.
  59. Why for update in submit?
    Locks the attempt row so concurrent submissions serialise; the second sees it already submitted.
  60. What does array_length return for an empty array?
    NULL. Hence coalesce(…, 0).
  61. How is a skipped answer encoded?
    -1, which never equals a valid 0-based index.
  62. What does distinct on (user_id) keep?
    The first row per user in the order by, here the best attempt (score desc, duration asc, earliest).
  63. Which functions can anon execute?
    Only get_leaderboard.
  64. Why is the rank lookup limit 100,000?
    A cap of 1,000 would make ranks beyond 1,000 come back NULL.
  65. Why clock_timestamp() for the duration?
    It is the real current time; now() is frozen at transaction start.
  66. How does the app avoid a theme flash?
    A classic inline script in <head> sets data-theme from storage before the body paints.
  67. Why put fallback HTML inside #root?
    Crawlers and slow connections see real content; React replaces it on mount.
  68. Why must og:image be absolute?
    Link-preview scrapers don't resolve relative URLs.
  69. What does manualChunks buy?
    Library code in separately hashed files, cached across deploys.
  70. Why is resolved computed, not stored?
    Derived state can't go out of sync with pref and the OS setting.
  71. What does detectSessionInUrl: false skip?
    Parsing magic-link tokens from the URL; we use OTP codes.
  72. Probability of any order under Fisher–Yates?
    1/n!.
  73. Which tsconfig flags make unused code fail the build?
    noUnusedLocals and noUnusedParameters.
  74. What does PostgREST error PGRST202 mean here?
    The function doesn't exist, so setup.sql hasn't been run.
  75. What does AnimatePresence add that React lacks?
    It keeps removed children mounted until their exit animation finishes.
  76. What does mode="wait" do?
    Mounts the next keyed child only after the previous one finished exiting.
  77. How does the tab pill glide between tabs?
    A shared layoutId; Motion animates the single element to its new position.
  78. Why did the page go blank on first run?
    useEffect(() => window.scrollTo(...)) returned a Promise; React called it as cleanup → destroy is not a function.
  79. Why must blocking UI never wait on an animation event?
    Hidden tabs and headless browsers may never fire it; the UI would stay blocked.
  80. What does an error boundary not catch?
    Errors in event handlers, async code, and the boundary itself.
  81. Why key the boundary by pathname?
    Navigating remounts it, clearing the error state.
  82. Why is the TopBar's scroll listener passive?
    It promises not to preventDefault, letting the browser scroll without waiting.
  83. Formula for the ring's dash offset?
    offset = C·(1 − v), with C = 2πr and r = (size − stroke)/2.
  84. Why rotate the ring SVG −90°?
    SVG strokes start at 3 o'clock; rotating starts the progress at 12.
  85. Ease-out cubic formula?
    e(p) = 1 − (1 − p)³.
  86. When does the sheet close on drag end?
    Offset > 110 px or downward velocity > 600 px/s.
  87. Why per-instance layoutId in Segmented?
    Equal layoutIds are treated as one element; two controls would share and fling one pill.
  88. What role and attribute make a toggle accessible?
    role="switch" with aria-checked on a real button.
  89. What does >>> 0 do in the hash?
    Truncates to an unsigned 32-bit integer.
  90. Why does useToast return as const?
    To type the result as a tuple, so destructuring gets precise types.
  91. Two steps of the logo cut-out?
    Flood-fill near-white from the edges to transparent; then keep only the largest connected foreground blob.
  92. Why redraw the mug as SVG?
    The bitmap had baked-in steam and a white handle hole; SVG is animatable, themeable and crisp.
  93. What does S do in a path?
    A smooth cubic curve whose first control point mirrors the previous curve's last.
  94. Why useId in CoffeeMug?
    Unique gradient and clip ids per instance.
  95. What makes icons take the text colour?
    stroke="currentColor".
  96. What does staggerChildren do?
    Delays each child's variant animation by a fixed step after the previous one.
  97. Why   in empty stat lines?
    Keeps tile heights equal before data arrives (no layout jump).
  98. What happens to steam under reduced motion?
    Animations collapse to ~0 ms and steam is shown fully drawn and opaque.
  99. What does ready prevent?
    A flash of the signed-out UI before the stored session and profile are loaded.
  100. Why maybeSingle() for the profile?
    New users have no row; zero rows must be null, not an error.
  101. Why defer work in onAuthStateChange?
    Awaiting Supabase calls inside the callback can deadlock on its internal lock.
  102. What was the "nobody can sign in" root cause?
    The app truncated codes to 6 digits; the project sends 8.
  103. Which OTP lengths does the app accept now?
    6–10; auto-submits at VITE_OTP_LENGTH (default 8).
  104. What does autoComplete="one-time-code" give users?
    One-tap fill of the code from Mail/Messages above the keyboard.
  105. Why noValidate on the email form?
    So the app's own message shows consistently instead of each browser's native popup.
  106. What does ?next=/test do?
    After session + profile exist, Account navigates there with replace: true.
  107. What finally caused the 504 on sign-up?
    Custom SMTP pointed at the website (psychology-of-learning-nptel.vercel.app:465), which has no mail server, so sending the code email hung until the gateway timed out.
  108. In "Sign in with Google" through Supabase, who receives Google's authorisation code?
    Supabase (at /auth/v1/callback). The app only ever receives Supabase's own code.
  109. What does detectSessionInUrl: true do?
    On start-up, supabase-js exchanges a ?code= in the URL for a session and removes it from the address bar.
  110. What does the PKCE verifier prove?
    That whoever exchanges the code is the same browser that started the sign-in; only that tab has the verifier.
  111. Which URL is the Google client's authorised redirect URI?
    https://kehcsupmruaskpgdvzaj.supabase.co/auth/v1/callback.
  112. What happens when redirect_to isn't in Supabase's allow-list?
    Sign-in works, but the user lands on the Site URL instead.
  113. Why can't you authorise vercel.app in Google Cloud?
    It's a public suffix; only a top private domain (suffix + one label) like psychology-of-learning-nptel.vercel.app can be authorised.

  342. Why open Lighthouse JSON as UTF-8 in Python on Windows?
    The default cp1252 codec can't decode some characters in the report.
  343. What does the `vercel.json` redirect do?
    Requests on the short domain get a permanent (308) redirect to the same path on the main domain.
  344. Why the SPA rewrite?
    So deep links and reloads serve index.html and React Router handles the path.
  345. What gets immutable caching?
    Only /assets/*, Vite's hashed files.
  346. When do VITE_ env changes take effect?
    At the next build; they're inlined into the bundle.
  347. Why .vercelignore in a Git-deployed project?
    CLI deploys upload the working folder, including untracked secrets.
  348. Which .gitignore pattern wins?
    The last one that matches.
  349. What did vercel link add to .gitignore, and the effect?
    .env* after !.env.example, re-ignoring the template.
  350. Risk of no framework preset?
    Source files served (HTML pointing at /src/main.tsx), 200 everywhere, app never runs.
  351. How to verify a deploy beyond status codes?
    The HTML references a hashed /assets/index-*.js; then npm run test:prod.
  352. Supabase settings the repo can't set?
    Running setup.sql, email templates with {{ .Token }}, OTP length, Site URL, SMTP.
  353. Why is /me not in the sitemap?
    It's the account page; nothing worth indexing.
  354. What is a maskable icon?
    An icon with safe padding so the OS can crop it to its own shape.
  355. Why can't the tests drive Google's login page?
    Bot detection, real credentials and 2-step verification in CI, and Google's terms. Test your side of the boundary instead.
  356. What does the hand-off test assert?
    The authorize request has provider=google, redirect_to = /me?next=%2Ftest, and a PKCE code_challenge; and the error return shows the message and keeps next.
  357. supabase-js's session storage key?
    sb-${hostname.split(".")[0]}-auth-token, e.g. sb-kehcsupmruaskpgdvzaj-auth-token.
  358. Why reload after writing the session to storage?
    The client reads storage only at start-up.
  359. What does session injection not prove?
    The Google redirect chain and the PKCE exchange.
  360. How do you assert an element is absent from the page?
    expect(locator).toHaveCount(0).
  361. Why do admin-minted codes still work with the Email provider off?
    The switch closes public email sign-in; minting via the admin API (secret key) and verifying still issue a session.
  362. The five probes, in order?
    Timed health/settings/REST; settings flags; the failing endpoint with a throwaway address; masked user listing; the dependency's port.
  363. Deny-list vs allow-list redaction?
    Deny-list hides names you predicted (and leaks the rest); allow-list shows only what you know is safe.
  364. Two habits that stop automation from hanging?
    < /dev/null (no stdin) and timeout N (a deadline).
  365. How do you prove a deploy is what users get?
    Fetch the live HTML, find the hashed entry chunk, grep it for a user-visible string unique to the new version.
  366. First move on a flaky test after your change?
    Read where it failed (error-context.md, screenshot, trace) before assuming your change caused it.
