L1.02

Prerequisites I: the web platform an app stands on

Recipe card
Time
70 min (skip sections whose self-check you ace)
You need

In two sentences: Every line of our app leans on a handful of browser features: HTML meta tags, CSS custom properties and media queries, promises and fetch, pointer events, localStorage, and the History API for routing. This lesson teaches exactly those, at the depth the later lessons need, and nothing else.

By the end, without notes, you can

  1. Explain what each <meta> tag in our index.html does, especially viewport with viewport-fit=cover.
  2. Explain how CSS custom properties plus prefers-color-scheme produce light and dark themes from one stylesheet.
  3. Write async/await code with fetch, and say what a Promise is and why returning one from the wrong place breaks things.
  4. Describe the pointer event sequence of a swipe, and what touch-action: pan-y changes.
  5. Explain how an SPA shows /study without the server having a study.html file.

2

The problem this solves

Frameworks hide the platform until something breaks. Then you need the platform. Three of this project's worst bugs were pure web-platform behaviour:

  • Chrome made window.scrollTo() return a Promise. That blanked the app (L2.05).
  • A sideways swipe triggered the browser's "go back" (L2.08a).
  • A scrollable box ate touch gestures (L2.08a).

You can only diagnose those if you know what the browser does underneath React.

3

HTML: the document and its meta tags

Self-check (skip §3 if all correct):

  1. What breaks on phones if you remove <meta name="viewport">?
  2. What does type="module" on a script change?
  3. What is <div id="root"> for in a React app?
Answersreveal
1. Phones pretend to be about 980 px wide and zoom out; text becomes tiny. 2. The script can use import/export, runs deferred (after parsing), and in strict mode. 3. It is the empty container React renders the whole app into.

3.1 What an HTML page is

Definition. An HTML file is a tree of elements. The <head> describes the page (title, metadata, styles). The <body> holds what you see.

Why here. Our app is an SPA, so index.html is nearly empty. It holds metadata for phones, search engines and link previews, plus one <div id="root"> and one script. React fills the rest.

The real file (trimmed to the parts this lesson explains; the full file is walked in L2.04):

HTML14 lines
<!doctype html><html lang="en">  <head>    <meta charset="UTF-8" />    <meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover" />    <title>Psychology of Learning NPTEL · Flashcards, Quiz &amp; Practice Test</title>    <meta name="theme-color" content="#0e0c0b" />    <link rel="manifest" href="/manifest.webmanifest" />  </head>  <body>    <div id="root"></div>    <script type="module" src="/src/main.tsx"></script>  </body></html>

Line notes:

  • L1<!doctype html>: tells the browser to use modern standards mode. Without it, browsers fall back to "quirks mode" with old, inconsistent layout rules.
  • L4charset="UTF-8": how bytes become characters. Without it, ·, – and ☕ can turn into garbage like Â·.
  • L5viewport → width=device-width: make the layout width equal the phone's width in CSS pixels (an iPhone 13 is 390). initial-scale=1: no zoom on load. viewport-fit=cover: let the page draw under the notch and the home indicator. That is why our CSS later adds env(safe-area-inset-*) padding: having asked to cover the whole screen, we must keep content out of the notch ourselves.
  • L7theme-color: the colour mobile browsers paint the address bar. We change it from JavaScript when the theme changes (L2.04).
  • L8manifest: a JSON file that makes the site installable ("Add to Home Screen") with a name and icons.
  • L11<div id="root">: React's mount point.
  • L12type="module": lets main.tsx use import. In development Vite serves that file translated to plain JS. In a build Vite rewrites this tag to point at the bundled assets/index-xxxx.js.

Try it (2 min). Open the live site, then DevTools → Elements. Expand <div id="root">: everything inside was created by JavaScript. Now View Source (Ctrl+U). In the raw HTML, #root contains only a fallback block for search engines (L4.08).

4

CSS you must know for this app

Self-check:

  1. What does var(--red) read, and where can --red be redefined?
  2. What does @media (prefers-color-scheme: dark) match?
  3. What is the difference between position: fixed and position: sticky?
  4. Why might transform: rotateY(180deg) show text mirrored?
Answersreveal
1. The value of the custom property --red inherited at that element; it can be redefined on any ancestor or in a media query. 2. When the OS or browser is set to dark mode. 3. Fixed is pinned to the viewport always; sticky scrolls normally until it reaches its offset (e.g. top: 0) inside its scroll container, then sticks. 4. Rotating 180° around the vertical axis shows the element's back side, which is its front drawn mirror-imaged, unless backface-visibility: hidden hides it.

4.1 Custom properties (CSS variables) and theming

Definition. --name: value defines a variable on an element. Children inherit it, and var(--name) reads it.

Why here. The app has one stylesheet that serves both light and dark mode. Every colour is a token like --bg, --ink or --red, and we redefine the tokens for dark mode in one place.

How it works. Analogy: tokens are labelled paint pots on a shelf. Components never say "beige". They say "the background pot". Swap what's in the pots, and the whole café repaints.

Minimal example (paste into an HTML file and open it; toggle your OS dark mode):

HTML8 lines
<style>  :root { --bg: #f6f0e6; --ink: #17110e; }  @media (prefers-color-scheme: dark) {    :root { --bg: #0e0c0b; --ink: #f4eadb; }  }  body { background: var(--bg); color: var(--ink); }</style><p>Same CSS, two themes.</p>

How the project uses it (from src/styles.css, explained fully in L2.10a): the light tokens live on :root. Dark tokens are defined twice: once in @media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) {…} } for "auto", and once on :root[data-theme="dark"] for "the user chose dark". JavaScript only flips the data-theme attribute.

What breaks without it. You would need a second stylesheet, or a class on every element. Both are easy to get wrong and drift apart.

4.2 Media queries and @supports

  • @media (min-width: 1024px) { … } applies rules only on wide screens. Our breakpoints are ≤ 300, ≤ 360, ≥ 640, ≥ 1024 and ≥ 1440 px, plus height-based ones (L2.10c).
  • @media (hover: hover) and (pointer: fine) means "this device has a mouse". We show keyboard-shortcut hints only there.
  • @media (prefers-reduced-motion: reduce) means "the user asked the OS for less motion". We almost disable animations.
  • @supports not (height: 100dvh) { … } applies rules only when the browser lacks a feature. We use it for old-Safari fallbacks.

4.3 Layout: flex, grid, fixed, sticky

  • Flexbox lays children in a row or column. Grid lays them in rows and columns (the stats tiles use grid-template-columns: repeat(3, 1fr)).
  • position: fixed pins to the viewport. That is our bottom tab bar.
  • position: sticky; top: 0 keeps the top bar at the top while you scroll. Gotcha: sticky sticks within its nearest scroll container. If an ancestor gets overflow: hidden, it becomes a scroll container and sticky stops working the way you expect. This is exactly why we used overflow-x: clip on <html> instead (L3.03).

4.4 Transforms and 3D

transform: rotateY(180deg) spins an element around its vertical axis. For a flip card you stack two faces. The back face starts at rotateY(180deg), and both faces get backface-visibility: hidden so only the face pointing at you shows. Safari did not honour that in our setup and showed the back mirrored over the front. Read the incident in L2.08a.

5

JavaScript: modules, promises, async/await, fetch, JSON

Self-check:

  1. What does an async function always return?
  2. What does await do to the surrounding function?
  3. What does fetch() resolve to for a 404?
Answersreveal
1. A Promise. 2. Pauses that function (not the whole page) until the promise settles, then continues with the value. 3. A Response with ok === false and status === 404; fetch only rejects on network failure.

5.1 Promises in one picture

Definition. A Promise is an object standing for a value that will exist later: pending → fulfilled (value) or rejected (error).

Analogy. The buzzer a café hands you. You can keep doing things; it buzzes when your coffee is ready.

Minimal example (DevTools console on any page):

JavaScript7 lines
async function demo() {  const res = await fetch("https://psychology-of-learning-nptel.vercel.app/robots.txt");  console.log(res.status, res.ok);      // 200 true  const text = await res.text();  console.log(text.split("\n")[0]);     // User-agent: *}demo();                                   // returns a Promise immediately

How the project uses it. Every Supabase call is a promise: const { data, error } = await supabase.rpc("start_test"). Supabase does not throw on errors; it returns error, so our code checks if (error).

What breaks if you misuse it. React's useEffect expects its callback to return nothing or a cleanup function. In Chrome, window.scrollTo(...) returns a Promise. We wrote useEffect(() => window.scrollTo({ top: 0 }), [...]). The arrow returned that Promise, React later tried to call it as cleanup, and the result was TypeError: destroy is not a function and a blank app. The full incident is in L2.05.

5.2 JSON

JSON.stringify({ s: "known", t: 1792068664692 }) gives '{"s":"known","t":1792068664692}', and JSON.parse reverses it. Storage only holds strings, so we JSON-encode everything we store. The questions file questions.json is JSON that Vite imports as a JS array.

6

DOM events: click, pointer, touch, keyboard, beforeunload

Self-check:

  1. In what order do pointerdown, pointermove and pointerup fire during a swipe?
  2. What does e.preventDefault() on a keydown for Backspace prevent?
  3. What does touch-action: pan-y on an element tell the browser?
Answersreveal
1. One pointerdown, many pointermove, one pointerup (or pointercancel if the browser takes over the gesture). 2. The browser's default action (in Safari, possibly navigating back). 3. "You may handle vertical panning (scrolling) yourself; leave horizontal movement to my JavaScript."

6.1 Pointer events and who owns a gesture

Definition. Pointer events unify mouse, pen and touch: pointerdown, pointermove, pointerup, pointercancel.

Why here. The flashcard swipe is a stream of pointer events, interpreted by the Motion library's drag (L2.08a).

How it works. When a finger moves, the browser must decide quickly: is this a scroll (the browser's job) or a drag (the page's job)? touch-action answers that in advance. If the browser decides it is a scroll, it sends pointercancel and the page never hears the rest.

Try it (2 min). In the console on any page:

JavaScript3 lines
addEventListener("pointerdown", e => console.log("down", e.pointerType));addEventListener("pointerup",   e => console.log("up"));addEventListener("pointercancel", e => console.log("CANCEL"));

Click: you see down mouse, then up.

6.2 Keyboard events and default actions

keydown gives e.key (" ", "ArrowRight", "Backspace", "1"). We listen on window for shortcuts and call e.preventDefault() for Space (otherwise the page scrolls) and Backspace (otherwise Safari may go back).

6.3 beforeunload

window.addEventListener("beforeunload", e => e.preventDefault()) asks the browser to show "Leave site?". We register it only while a test is running, so a stray swipe-back or tab close doesn't silently lose your attempt.

7

Storage: localStorage and sessionStorage

Self-check:

  1. What type do localStorage values have?
  2. When can localStorage.setItem throw?
  3. How is sessionStorage different?
Answersreveal
1. Strings only. 2. In some private modes, when the quota is full, or when storage is blocked by settings. 3. It lasts only for that tab's session; closing the tab clears it.

How the project uses it. src/lib/storage.ts wraps both calls in try/catch and JSON (walked in L2.04). sessionStorage remembers "the splash was already shown in this tab" so the splash appears once per visit, not on every reload.

What breaks without the try/catch. In a locked-down browser the very first setItem throws, and the app crashes on load instead of working without persistence.

8

HTTP and JSON APIs

Self-check:

  1. What is the difference between status 200, 401, 403 and 404?
  2. What does a 308 response with a Location header do?
  3. What does the header Cache-Control: public, max-age=31536000, immutable mean?
Answersreveal
1. OK; not authenticated; authenticated but not allowed; not found. 2. Permanent redirect, keeping the method; the browser goes to Location. 3. Any cache may keep it for a year and never revalidate. Safe only when the file name changes whenever the content does (hashed asset names).

Definition. HTTP is request → response. A request has a method (GET, POST), a URL, headers and an optional body. A response has a status, headers and a body.

Where you will see this. The live security tests in L4.06 send exactly these requests and expect error code 42501 for anonymous start_test. The HTTP tests in L4.03 check our redirect (308) and cache headers.

9

URLs, the History API and SPA routing

Self-check:

  1. In /study?week=3, what is the path and what is the query?
  2. How does an SPA change the URL without reloading?
  3. Why must the host rewrite /study to /index.html?
Answersreveal
1. Path /study; query week=3. 2. history.pushState() or replaceState() change the URL and add history entries without a request; the app listens and renders the matching screen. 3. If someone opens or refreshes /study directly, the server receives that request; there is no study file, so without a rewrite to index.html they get a 404.

Try it (1 min). On the live site, click Study → Ranks with the Network tab open. No new HTML request appears. Then press F5 on /ranks. Now one HTML request appears, and it returns 200 thanks to the rewrite.

Check yourself

Answer each one before you look. Multiple-choice questions mark your pick and let you try again; for open questions, answer aloud, then reveal and grade yourself honestly.

Q1
You remove viewport-fit=cover but keep the safe-area padding. On an iPhone, what changes?
B. Without cover the browser keeps the page inside the safe area itself, and the insets evaluate to 0. A is the opposite risk: having cover without the padding. D happens when you remove the whole viewport tag.
Q2
Which useEffect is wrong?
B. A concise arrow returns its expression, and here that is a Promise in current Chrome. React treats a returned value as a cleanup function and later calls it: destroy is not a function. The braces in A and D make the arrow return undefined. C correctly returns a cleanup function.
Q3
A swipe on the card moves the page sideways and the browser navigates back. Which CSS property fixes the navigation part?
B. Overscroll navigation is the browser's "swipe past the edge to go back". overscroll-behavior-x: none disables it. A would kill all scrolling. D could break sticky headers and does not stop overscroll navigation.
Q4
Opening https://…/ranks directly returns 404 on a new host. The most likely cause?
B. The 404 comes from the server before any JavaScript runs. A would show a blank page or the wrong screen, not a server 404.
Right so far: 0 of 4

13

Flashcards

See all 8 cards as a listfor a quick scan
  1. What does viewport-fit=cover oblige you to do in CSS?
    Pad content with env(safe-area-inset-*) so it stays out of the notch and home-indicator areas.
  2. Why are dark tokens written twice in our CSS?
    Once under prefers-color-scheme: dark for "auto" (unless the user forced light), once under [data-theme="dark"] for an explicit dark choice.
  3. What must a useEffect callback return?
    Nothing, or a cleanup function. Never a Promise or any other value.
  4. What does pointercancel mean for a swipe?
    The browser took over the gesture (usually to scroll); the page gets no further moves or pointerup.
  5. Why wrap localStorage in try/catch?
    It can throw in private modes, when full, or when blocked. Crashing on load is worse than losing persistence.
  6. Why does an SPA host need a catch-all rewrite?
    Direct visits or refreshes of client routes reach the server, which has no such file; the rewrite serves index.html so the router can render the route.
  7. When is Cache-Control: immutable safe?
    When the filename changes with the content (hashed build assets), so a new version always has a new URL.
  8. Why can overflow: hidden on an ancestor break position: sticky?
    It makes that ancestor a scroll container; sticky then sticks relative to it, not the viewport.

Glossary

Custom property
CSS variable --x read with var(--x).
Default action
what the browser does for an event unless preventDefault() is called.
History API
pushState/replaceState/popstate for URL changes without reloads.
JSON
text format for data.
Media query
CSS applied only when a condition matches.
Pointer events
unified mouse/touch/pen events.
Promise
object for a future value.
Rewrite
server serves a different file than the URL names, keeping the URL.
Safe area
screen region not covered by notches or rounded corners.
Scroll container
element that scrolls its overflowing content.
Standards mode
modern rendering mode triggered by <!doctype html>.
touch-action
CSS telling the browser which touch gestures it may handle.
Viewport
the visible area the layout is computed for.
