The problem this solves

A brand makes the app recognisable, but raw logo files fight the UI. The black-and-white artwork vanished on dark backgrounds, the white boxes looked pasted-on in dark mode, and a static mug can't express "brewing". We needed transparent cut-outs, proper app icons, and a mug we could animate.

3

Concepts

3.1 Removing a white background: flood fill, then the largest component

Plain idea. Every white pixel you can reach from the image's edge, without crossing a non-white pixel, is background. White pixels inside the artwork (the mascot's sunglasses glint, enclosed by black outline) are not reachable from the edge, so they stay.

Steps (Python + Pillow; the real script, slightly condensed):

Python41 lines
from PIL import Image, ImageFilterfrom collections import deque def cutout(path, thr=40):    im = Image.open(path).convert("RGBA"); w, h = im.size; px = im.load()    dist = lambda p: 255 * 3 - (p[0] + p[1] + p[2])      # 0 for pure white    bg = [[False] * h for _ in range(w)]    q = deque([(x, 0) for x in range(w)] + [(x, h - 1) for x in range(w)] +              [(0, y) for y in range(h)] + [(w - 1, y) for y in range(h)])    while q:                                              # 1) flood fill from all edges        x, y = q.popleft()        if not (0 <= x < w and 0 <= y < h) or bg[x][y] or dist(px[x, y]) > thr: continue        bg[x][y] = True        q.extend(((x + 1, y), (x - 1, y), (x, y + 1), (x, y - 1)))    mask = Image.new("L", (w, h), 255); m = mask.load()    for x in range(w):        for y in range(h):            if bg[x][y]: m[x, y] = 0    edge = mask.filter(ImageFilter.MinFilter(3)); e = edge.load()   # 2) soften the rim    for x in range(w):        for y in range(h):            if m[x, y] == 255 and e[x, y] == 0:                m[x, y] = max(0, min(255, int(dist(px[x, y]) * 255 / 300)))    # 3) keep only the largest 8-connected blob (drops pieces of neighbouring stickers)    seen = [[False] * h for _ in range(w)]; best = []    for sx in range(w):        for sy in range(h):            if seen[sx][sy] or m[sx, sy] == 0: continue            comp, q = [], deque([(sx, sy)]); seen[sx][sy] = True            while q:                x, y = q.popleft(); comp.append((x, y))                for dx in (-1, 0, 1):                    for dy in (-1, 0, 1):                        nx, ny = x + dx, y + dy                        if 0 <= nx < w and 0 <= ny < h and not seen[nx][ny] and m[nx, ny] > 0:                            seen[nx][ny] = True; q.append((nx, ny))            if len(comp) > len(best): best = comp    keep = Image.new("L", (w, h), 0); k = keep.load()    for x, y in best: k[x, y] = m[x, y]    im.putalpha(keep)    return im.crop(keep.getbbox())                        # trim empty borders

Notes:

  • dist is "how far from white": 0 for (255,255,255). thr=40 treats near-white (JPEG-ish noise) as background. The mascot had a grey sticker halo and needed thr=110.
  • BFS with a deque (breadth-first search: visit neighbours level by level): 4-neighbour fill for the background. A recursive version would overflow the stack on a 1536×1024 image (1.5 million pixels).
  • Rim softening: pixels right next to the background get partial alpha proportional to their darkness. That anti-aliases the edge, so there's no white fringe on dark themes.
  • Largest component: 8-neighbour connectivity. See the incident in §7.
  • getbbox(): the bounding box of non-zero alpha, used to crop the margins.

3.2 SVG paths in five minutes

An SVG <path d="…"> is a pen: commands move or draw, with numbers as coordinates in the viewBox.

Command Meaning Example from the code
M x y move (pen up) M36 104 starts the mug body
L x y straight line L 156 104 the rim edge
H x / V y horizontal / vertical line icon home: V20
C x1 y1, x2 y2, x y cubic Bézier curve: two control points, then the end C 64 74, 92 64, 78 44 a steam S-bend
S x2 y2, x y smooth cubic (first control point mirrored from the previous curve) S 72 20, 84 8 continues the S
A rx ry rot large sweep x y elliptical arc icon timer circle
Z close the shape end of the body
lower-case (l, a, h) relative to the current point icons use a1 1 0 0 1-1 1 for rounded corners

viewBox="0 0 200 230" defines the drawing's own coordinate space; width/height scale it. That is why <CoffeeMug size={84}> and size={150} are the same drawing at different sizes.

3.3 Animating a line being "drawn"

The ring trick from L2.06a, reused: set stroke-dasharray: 160 (a dash longer than the steam path) and animate stroke-dashoffset from 160 (hidden) to 0 (fully drawn) to -150 (sliding away). Combined with a rise (translateY) and fade, each wisp seems to curl up and vanish.

transform-box: fill-box + transform-origin: 50% 100%: by default, SVG transforms use the whole SVG's origin (its top-left corner). fill-box makes 50% 100% mean "the bottom-centre of this path", so each wisp scales and rises from its own base.

(The real file has one declaration per line; it's condensed here for reading.)

  • Staggered delays (0, 0.55 and 1.1 s over a 3.2 s cycle): the wisps never move in sync, which reads as natural steam.
  • bob: a keyframe with only 50% means it eases from the element's normal state to that pose and back. A floating mug on Home.
  • fill … alternate: plays forwards, then backwards, forever: pour, drain, pour.
  • Reduced motion (end of styles.css): all animations shrink to 0.001 ms, and steam is shown fully drawn (dashoffset: 0; opacity: 1) instead of invisible.

Bug journal

Incident ticket · #01

Cut-out logos carried pieces of neighbouring stickers

Fixed
  1. Symptom
    On a contact sheet of the cut-outs against dark and light backgrounds, the mug had a black arc floating above it, the hexagon badge a red arc on its right, and the sticker and round badge had fragments at their sides.
  2. Diagnosis
    The source PNGs were crops from a sticker sheet: the edges of neighbouring stickers poked into each crop. Flood fill correctly removed the white between them, but the fragments weren't white, so they stayed as separate islands of opaque pixels.
  3. Root cause
    "Not background" is not the same as "the subject". The algorithm had no notion of which foreground was the logo.
  4. Fix
    After masking, label the connected foreground regions (BFS, 8-connectivity) and keep only the largest. The mascot also had a grey halo, so its threshold went 40 → 110.
    Diff6 lines
        im.putalpha(mask)    return im.crop(mask.getbbox())    # keep only the largest connected foreground blob (drops neighbouring sticker fragments)    … BFS labelling, best = largest component …    im.putalpha(keep)    return im.crop(keep.getbbox())
  5. Lesson
    Look at image-processing output on both target backgrounds before shipping. A contact sheet made the problem obvious in one glance.

Design incident · The mug PNG couldn't be used for animation. The mug image had its steam baked in, and the inside of its handle was solid white (not reachable by the edge flood fill). Trying to paint the steam out of the coffee pixel by pixel left smudges. Decision: redraw the mug as SVG (≈ 40 lines of paths), which also made it theme-aware and crisp at every size. Lesson: when a bitmap fights you, a vector redraw is often faster than repair.

Check yourself

Answer each one before you look. Multiple-choice questions mark your pick and let you try again; for open questions, answer aloud, then reveal and grade yourself honestly.

Q1
Two <CoffeeMug>s on one page without useId. What could go wrong?
Did you have it?
Duplicate gradient and clip-path ids. The second mug's url(#coffee) may resolve to the first's definition, and if that mug unmounts, the reference can break.
Q2
Remove transform-box: fill-box from .steam path. What changes?
Did you have it?
Transforms use the whole SVG's origin (its top-left corner), so scaleX and the rise distort every wisp around the wrong point. The wisps drift sideways instead of curling up from their bases.
Q3
Why draw each wisp twice?
Did you have it?
The first, thicker stroke in the edge colour forms an outline under the coloured stroke. That makes the sticker look, and keeps the cream wisp visible on light backgrounds.
Q4
stats?.best_score || "–" instead of ??. Which student sees the wrong thing?
Did you have it?
One whose best score is 0: 0 || "–" is "–". ?? only falls back on null or undefined.
Q5
Why was the white inside the mug handle not removed by flood fill?
Did you have it?
It's enclosed by the dark handle outline, so it's not reachable from the image's edge without crossing non-white pixels.

Flashcards

See all 8 cards as a listfor a quick scan
  1. Two steps of the logo cut-out?
    Flood-fill near-white from the edges to transparent; then keep only the largest connected foreground blob.
  2. Why redraw the mug as SVG?
    The bitmap had baked-in steam and a white handle hole; SVG is animatable, themeable and crisp.
  3. What does S do in a path?
    A smooth cubic curve whose first control point mirrors the previous curve's last.
  4. Why useId in CoffeeMug?
    Unique gradient and clip ids per instance.
  5. What makes icons take the text colour?
    stroke="currentColor".
  6. What does staggerChildren do?
    Delays each child's variant animation by a fixed step after the previous one.
  7. Why   in empty stat lines?
    Keeps tile heights equal before data arrives (no layout jump).
  8. What happens to steam under reduced motion?
    Animations collapse to ~0 ms and steam is shown fully drawn and opaque.
